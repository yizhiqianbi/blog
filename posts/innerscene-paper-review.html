Exploring Inner-Space
Scene Generation

Capture Setup · Dataset Building · Algorithm Design · Applications

第一个面向密集储物空间的大规模 3D 场景数据集与生成框架。论文同时贡献了一套消费级硬件的真实采集 pipeline、含 10,821 个真实场景的 InnerScene 数据集,以及一个 VLM + Flow-Matching Diffusion + Physics 三段式 layout 生成算法。

3D Scene Generation Multi-Object Layout VLM Reasoning Flow Matching Embodied AI

核心一句话

把"往柜子里塞东西"这件事,拆成
语义理解 → 几何精修 → 物理兜底 三段,分别让不同模型处理。

Problem. 现有 3D 室内场景数据集的柜子、冰箱、抽屉里几乎都是空的,这与真实世界严重脱节,导致 embodied AI 在密集储物场景里无数据可学。

Data. 用 8 相机消费级装置 + "假墙真约束"(用 tape 和绳子模拟容器边界)+ 渐进式录视频(而非拍最终态)的方法,采集了 10,821 个真实场景,涵盖 8 类容器、240+ 类物体、每场景 15–25 件。

Algorithm. Stage 1 用 LoRA 微调的 Qwen3-VL-8B 做粗 layout + 输出 stacking 关系图;Stage 2 用一个 Flow-Matching Transformer(SiT 架构 + Utonia 点云特征 + GNN 注入 scene graph)精修到 6-DoF;Stage 3 用 Blender Bullet 做物理 settle 兜底。

Result. 在 VLM 评估、人类感官、物理稳定性上全面超越 GPT/Gemini 零样本和经典 Bin Packing。Win Rate 56.7% vs Rule-Stack 23.3%,物理稳定性 100%。

§ 1 · MOTIVATION

问题:大家都忽视了"装满"的柜子

这篇论文的切入点非常具体。作者观察到一个常被忽视的现象:虽然 ScanNet、Matterport3D、3D-FRONT 等数据集已经覆盖了相当多的室内场景,但这些场景里的储物空间几乎全部是空的。冰箱里没东西、橱柜里没东西、抽屉里也没东西。然而真实世界里,人和机器人每天大量的交互正是发生在这些装得满满当当的内部空间里——做饭从冰箱里找食材、整理从橱柜里取餐具。

这种数据缺失带来两个具体的研究空白:一是 embodied AI 训练时没有真实的密集容器数据;二是 3D 场景生成方法在面对"容器约束 + 密集堆叠 + 物体间支撑关系"这种复合任务时基本失效。

更难的是,密集储物场景的特点决定了它很难直接采集。冰箱、橱柜的内壁本身就遮挡了所有外部视角,而内部物体相互之间又有严重的二次遮挡。这导致传统的 RGB-D 扫描、photogrammetry、SLAM 方法都无法直接套用。

作者的整篇论文,本质上是在回答一个问题:既然我们承认这个数据空白存在,那么——怎么把它系统地填上?

这个问题被拆成三个子问题来回答:数据怎么采(§2)、算法怎么设计(§3)、效果怎么验证(§4)。下面逐一拆解。

§ 2 · DATA COLLECTION

数据采集:把墙拆掉,把时间拉开

这一节是论文最有"工程美感"的部分。作者从 first principles 出发,识别出密集储物场景采集的两个不可观测层次,并分别给出对应的破解办法。

问题 · 两层遮挡

容器墙挡视野 + 物体相互遮挡

  • 真冰箱、真柜子内壁挡住几乎所有外部相机视角
  • 放进去一堆物体后,后面的物体被前面的盖住
  • SAM / VGGT / MASt3R 都需要至少一个清晰视角才能注册 pose
  • RGB-D 在反光、深色、深景里基本失效
方案 · First Principles 解耦

用约束代替墙,用视频代替静态拍摄

  • 空间约束 ≠ 视觉墙体:用桌面胶带画底面 + 绳子拉高度限制
  • 8 个相机 360° 包围,因为墙不存在了所以视野畅通
  • 放物体的过程录视频,不只拍终态
  • 从视频里抽出"每个物体刚放下、还没被遮挡"那一帧
关键洞察

用渐进式时序采集,绕过密集场景的不可观测性

这个 trick 的本质是:密集状态的 3D 注册问题,可以转化为一系列稀疏状态的注册问题。每个物体在被放进去的那一帧,场景里最多只有它一个新物体,其他物体的 pose 上一帧就已经知道。这把一个组合爆炸的难题,变成了 N 个独立的、可解的子问题。

从信息论角度看,作者把"时间维度"当作一种额外的观测信号引入,补偿了"空间维度"上的视角不足。这个思路在很多遮挡严重的场景(手术、装配、密集人群)都可以借鉴。

§ 3 · ALGORITHM

算法核心:VLM 想 · Diffusion 算 · Physics 兜

论文最核心的算法设计哲学是:不要让一个模型干所有事。密集 layout 需要的能力分布在三个完全不同的层面,应该用三种擅长不同任务的模型分别处理。

  • ① 语义层 — 哪些物体应该堆叠?谁支撑谁?哪些应该靠近?用 VLM。
  • ② 几何层 — 具体的 6-DoF 在哪?如何避免碰撞和悬空?用 Diffusion。
  • ③ 物理层 — 微小穿模和悬浮怎么消?用刚体仿真。
STAGE 1
VLM 语义规划
Qwen3-VL-8B-Thinking + LoRA · 用 CoT 推理输出粗 layout 中心点 + Scene Graph(谁支撑谁)
输出: coarse centroids + DAG
▸
STAGE 2
Diffusion 几何精修
Flow-Matching SiT · Utonia 点云特征 + GNN 注入 scene graph · 跨物体 attention · 输出去噪后的精确点云
输出: 6-DoF poses (via Kabsch)
▸
STAGE 3
Physics 兜底
Blender Bullet · 凸包分解防爆 · 高 damping=0.8 防整体崩塌 · quasi-static settle 消除微穿模
输出: 100% 物理稳定
1

VLM 当语义规划器

Qwen3-VL-8B-Thinking · LoRA · Chain-of-Thought

输入:N 个物体的 RGB 图 + 3D bbox 尺寸 + 容器尺寸。VLM 被强制输出一个三步 CoT 推理链:

① Affordance analysis — 这个物体重不重?能不能被堆在上面?能不能堆别的东西在它上面?
② Layer planning — 确定垂直分层:什么在底层、什么在中层、什么在最上面
③ Spatial allocation — 在 XZ 平面上分配位置

关键产出有两个:coarse centroids 每个物体的粗中心点坐标,scene graph 一个有向无环图,边表示 "A 物体被 B 物体支撑"。

训练方式:用一个大的闭源模型(GPT/Gemini)对 GT layout 做 rationalization,生成符合 JSON 格式的 CoT 标注,然后用 teacher-forcing 教 Qwen3-VL。这是个非常实用的蒸馏 + 格式约束组合拳——既复用了大模型的推理能力,又把它压缩到 8B 可控的规模,同时保证输出严格符合下游解析格式。

消融实验里可以看到,这一步对 JSON 格式遵循率从原始 Qwen3-VL 的不稳定提升到了 100%。

2

Flow-Matching Transformer 做几何精修

PackingTransformer · SiT 架构 · Utonia 点云特征 · GNN 注入

VLM 出来的 centroids 经常飘——尤其是 Y 轴(高度)。论文给的解释很到位:VLM 没见过足够多的 3D 数据,且没有 fine-grained mesh 几何感知(它只看 bbox 尺寸)。所以需要一个真正"看得见几何"的模型来精修。

每个物体下采样到 K=500 点,共 N×500 个点。每个点通过一个 frozen 的 Utonia encoder 提取 1386-维几何特征。整个网络做的事可以分三层来看:

Flow Matching 目标 — 从 Gaussian 噪声 x₀ 线性插值到真值 x₁,网络回归速度场 v* = x₁ − x₀
三种 attention 交替 — Intra-object(同物体内的点) → Support-Graph GNN(沿支撑边传消息) → Inter-object(全局)
深度 — L=4 个 block,每个 block 都用 AdaLN-Zero 调制 timestep 条件
x_t = (1−t)·x₀ + t·x₁ ;   L_FM = E ‖v_θ(x_t, t, F_geo, G) − (x₁−x₀)‖²

最关键的设计:Scene Graph 不是辅助输入,而是结构上注入到 GNN 层中。也就是说,VLM 说"杯子在书上",这个支撑关系就变成 GNN 中一条边,让 diffusion 在生成杯子点云的位置时必须"顾及"书的位置。这是个很优雅的分工——VLM 提供拓扑约束,Diffusion 在拓扑约束下做几何回归。

SE(3) 恢复(Kabsch 算法):Diffusion 输出的点云会有微小的非刚性形变(因为它在连续空间操作)。论文用 Kabsch 算法对每个物体的原始 mesh 点和预测点做 SVD-based registration,提取出严格刚性的 R, t,再 apply 到原始 mesh 上。这一步保证了最终输出仍然是刚体变换而非扭曲的网格——这是个干净的工程细节,常被忽视但很重要。

训练时还用了两个 trick:progressive SE(3) noise curriculum(随训练加深加强扰动)和 10% 概率的 Classifier-Free Guidance dropout。推理用 SDE Euler 100 步采样。

3

Blender 物理兜底

Bullet engine · Convex Hull Decomposition · Damping 0.8

论文坦白承认:data-driven 生成模型本质是统计先验,数学上无法保证 100% 物理正确。所以加了一个 fail-safe:把所有物体设为 rigid body,在容器底部放一个静止支撑面,做几秒钟自由落体仿真。

但是有两个关键 trick 防止它毁掉精修结果:

① Convex Hull Decomposition — 非凸物体(碗、盆)如果直接用原始 mesh 做碰撞体,在初始化时会因为细小穿模产生爆炸性排斥力,把整个场景炸飞。所以先做凸包分解作为碰撞代理。

② 极高 damping = 0.8(平移和旋转都是)— 这样物体不会因为初始小穿模而被弹飞,只会缓慢沉降到稳定位置。保留了 VLM + Diffusion 精心安排的整体结构。

这是个 quasi-static relaxation,本质上不是真正的动力学仿真,而是把生成结果投影到物理可行解流形上的最近点。从信息论角度看,这一步消除的是 diffusion model 残留的、统计上微小但物理上致命的偏差——比如 0.5mm 的穿模在视觉上看不出来,但物理仿真里会让物体抖动甚至飞起来。

§ 4 · RESULTS

实验结果:每一阶段都不可省

论文的实验设计相当严谨。Baseline 既包含经典的几何启发式(Extreme-Point Bin Packing、自研的 Rule-Stack),又包含强大的闭源 VLM(GPT、Gemini)零样本。评估也用了两套:Gemini 2.5 Pro 当判官从 5 个维度打分(realism、density、supporting、placement、semantic),以及 Blender 物理仿真测稳定性。

观察 · 1

GPT / Gemini 零样本做 3D layout 完全不够

哪怕是最强的闭源 VLM,在精确 3D 坐标回归这种任务上表现都很差——Semantic 评分只有 2.0~2.3,物理稳定性只有 50%~60%。这印证了一个公认的观察:VLM 擅长定性推理(逻辑、关系、约束),但不擅长定量回归(数值、坐标、尺度)。

这个观察很重要,因为它说明:把 LLM/VLM 直接当 layout 生成器是行不通的。必须有一个专门的几何模型来做精确部分。论文用一个 8B 微调模型 + 一个 diffusion 后处理,就能干翻 GPT 闭源 + 零样本——证明了"分工"比"堆模型"更有效。

观察 · 2

Extreme-Point 100% 物理稳定的代价是"完全不堆叠"

注意 Extreme-Point Packing 的 Physical Stability 也是 100%——但这并不是因为它聪明,而是因为它从不尝试堆叠。所有物体都平铺在底面,自然就稳定。这暴露了一个问题:只看物理稳定性会高估纯几何方法的能力,所以必须同时看语义评分。Extreme-Point 的 Realism 只有 2.60,远低于本文方法的 4.10。

观察 · 3

Diffusion 才是最大的跳变,Physics 是最后一公里

从 Qwen Tuned (1.88) 到 Diffusion (4.25),Semantic 翻了一倍多——这印证了几何精修是把 layout 从"勉强能看"提升到"像样"的关键。注意这里 Diffusion 阶段的 Physical Stability 是 84.5%,说明仅靠 Diffusion 已经能消除大部分穿模和悬浮,但还是有 15% 左右的边界 case。

Physics settle 这一步贡献相对小(4.25 → 4.75)但对物理可用性是 84.5% → 100% 的跳变。也就是说,如果下游是视觉评估,可以不要 Stage 3;如果下游是embodied AI 仿真,Stage 3 几乎是必须的。这种"按需配置"的清晰边界,是这篇论文 ablation 设计得很漂亮的地方。

§ 5 · LIMITATIONS

局限与开放问题

论文在结论里相当诚实地列出了局限性,以下把作者承认的和我自己读下来观察到的合并归纳:

作者承认的

当前框架的局限

  • 只处理规则的 box 状容器,不支持复杂内部结构(洗碗机的支架、冰箱的隔层)
  • 只处理刚体,不支持可变形物体(衣服、塑料袋、电缆)
  • 只生成静态 layout,不模拟"放置过程"的动力学
  • 采集需要 8 相机硬件 + 手机重建,虽然可规模化但仍有成本
读下来的额外观察

方法本身的开放问题

  • VLM 在 Y 轴(高度)回归仍然弱,完全依赖 Diffusion 补救
  • Scene Graph 只表达"支撑"关系,无法表达"包含"、"穿过"、"卡扣"等复杂关系
  • Diffusion 用 500 点采样,对薄、长、细的物体几何表达可能不够精细
  • 评估完全依赖 Gemini 2.5 Pro 当判官,存在 LLM 评估的固有偏差
  • 没有探讨"放置顺序"——同样一组物体不同放置顺序应该有不同最优解

作者在 future work 里明确提到一个有意思的延伸方向:把数据集用于训练 embodied agent,从静态 layout 生成进化到机器人可执行的动态 rearrangement。这个方向其实更接近真正的应用价值——储物场景的最终用户不是图形渲染,而是抓取、整理、归位这些 embodied 任务。

另一个值得思考的方向是从 layout 反推语义。论文做的是 "objects + container → layout";反过来,给定一个 layout,能不能推断出场景的语义(这是厨房还是浴室、用户是收纳达人还是邋遢党)?这种逆向推断在用户建模和个性化推荐里有应用。

§ 6 · TAKEAWAYS

读完之后值得记住的几件事

跳出这篇论文具体的"做什么",有几个方法论层面的 takeaway 是可以迁移到其他研究的:

① 数据采集的 first-principles 思维。 作者没有去硬磕"怎么让 RGB-D 在容器里 work",而是反问"我们为什么需要墙?"——发现墙的作用只是空间约束,那就用 tape 模拟约束、把墙拿掉。这种解耦视觉信号和物理约束的思路很值得学习。

② 任务的能力分层。 复杂任务往往需要多种能力上互补的模型。VLM 擅长语义但不擅长精确数值,Diffusion 擅长连续空间回归但不懂高级语义,Physics engine 提供硬约束但需要好的初始解。这三者组合起来,每个模型只做自己最擅长的事——这种分工比训一个端到端大模型更鲁棒、更可解释。

③ 中间表达的设计。 Scene Graph 作为 VLM 和 Diffusion 之间的接口是这篇论文最优雅的设计。它足够抽象(只有节点和边),所以 VLM 容易生成;它足够结构化(DAG),所以 Diffusion 可以通过 GNN 直接消费。中间表达的好坏,往往决定了多阶段系统能不能 work。

④ Generation + Verification 的组合。 Stage 3 的 Physics settle 不是一个"更好的生成器",而是一个"把生成结果投影到合法解空间"的 verifier。承认生成模型有统计误差,然后用一个 cheap 的后处理来 close the loop——这种思路在 code generation、math proof、protein design 里也都开始出现。

这篇论文最值得欣赏的不是某一个技术点,而是整体的工程哲学: 承认每个组件的局限,用组合代替万能,用验证代替信仰。
