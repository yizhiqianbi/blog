Talk Notes · Cosmos 3

Cosmos 3 组会讲稿：把 MoT、Action Token 和 mRoPE 讲成一条线

这份讲稿不是复述 Cosmos 3 全文，而是把汇报主线压成一个系统问题： Physical AI 里的理解、生成、动作，能不能放进同一个 token/attention/position/loss 接口？

2026.06.23 阅读约 18 分钟 Cosmos 3 · Talk Script

0. 一句话结论

Cosmos 3 的讲法应该避开“又一个视频生成模型”。更准确的定位是： 它试图把 VLM 的理解、world model 的想象、VLA/WAM 的动作输出 改写成同一个序列系统。核心不是模态多，而是任务差异被压缩成 clean/noisy token layout。

主线
从割裂的 VLM / video generator / VLA，走到 AR Reasoner + DM Generator 的统一 backbone。
听众要记住
MoT 分开 reasoning 和 denoising；action token 表示状态转移；3D mRoPE 把 video、audio、action 放到同一条物理时间轴。
汇报风格
先讲系统接口，再讲公式。不要先报参数和榜单，否则听众会把它误解成视频模型 scale-up。

1. 开场怎么讲

开场可以直接问：Physical AI 里的模型到底应该只会“看懂世界”，只会“生成未来”，还是要同时理解、预测和行动？ Cosmos 3 的答案是第三个。

过去我们常把系统拆开：VLM 看懂当前画面，world model 想象未来，policy 或 VLA 输出动作。这个 pipeline 很自然，但接口很碎。

所以这次讲 Cosmos 3，不要按技术报告顺序从数据讲到评测。更好的顺序是： 问题割裂 → 统一序列 → MoT → action token → mRoPE → 训练/推理系统。

2. 用一张表讲清楚任务统一

Cosmos 3 最重要的抽象是：Generator 统一做一件事，给定 clean condition tokens，denoise noisy target tokens。 任务类型不是靠换模型完成，而是靠换 token 布局完成。

模式 Clean condition Noisy target 现场口播重点
VLM text / image / video in AR none 只走 Reasoner，像视觉语言模型。
T2V / I2V text，或 text + initial frames future VAE video tokens 把视频生成看成 conditional denoising。
Forward dynamics observed video + clean action future video 回答“如果这样动，未来会怎样”。
Inverse dynamics before / after video action tokens 回答“这个变化需要什么动作”。
Policy observation + goal action + future video 动作和视觉后果共同生成。

3. MoT：不是把 VLM 和 diffusion model 粗暴串起来

MoT 的核心不是传统 MoE 那种动态专家路由，而是在每个 decoder block 里固定拆出两条参数路径： Reasoner path 处理 AR subsequence，Generator path 处理 diffusion subsequence。

\[ O_{AR}=\operatorname{Attn}_{causal}(Q_{AR},K_{AR},V_{AR}) \]
\[ O_{DM}=\operatorname{Attn}_{full}(Q_{DM},[K_{AR};K_{DM}],[V_{AR};V_{DM}]) \]

现场讲的时候要强调信息方向：AR token 不被 noisy DM token 更新；DM token 可以读 AR context。 这样 Reasoner 保持干净语义上下文，Generator 用这些上下文去做高维连续 denoising。 

AR subsequence:
  language tokens + ViT visual tokens
  -> Reasoner tower
  -> causal next-token prediction

DM subsequence:
  VAE vision + audio + action tokens
  -> Generator tower
  -> full-attention rectified-flow denoising

Information flow:
  AR -> DM allowed
  noisy DM -> AR blocked

4. Action token：把动作讲成 transition

Cosmos 3 里 action token \(a_t\) 放在 \(v_{t-1}\) 和 \(v_t\) 中间，所以它不是“第 t 帧的控制量”，而是连接相邻视觉状态的转移：

\[ a_t:\ v_{t-1}\rightarrow v_t \]

这句话适合在 slide 5 多停一下。它解释了为什么 forward dynamics、inverse dynamics、policy 可以是同一套模型： 只要改变哪个 token 是 clean，哪个 token 是 noisy，训练目标就从“预测后果”切换到“反推动作”或“联合生成策略”。

对 FastWAM 或自己的 WAM 工作，这里的可复用点不是直接照搬模型规模，而是： 先把 action 定义成状态转移，再用 world model 学 action 和未来视觉的对应关系。

5. mRoPE：讲成物理时间轴，不要讲成普通位置编码

Cosmos 3 的序列里混着 text、video、audio、action。它们的 token index 不等价于物理时间： 视频有 FPS 和 VAE temporal compression，音频有 hop size，动作有控制频率。

Token 类型 坐标 为什么这样讲
Language (i,i,i) 让 3D mRoPE 对文本退化成 1D RoPE，兼容预训练 VLM。
Video (t,h,w) 保留时间和空间格子。
Audio / Action (t,0,0) 没有空间网格，只需落在正确物理时间点。
AR/DM margin gap=15000 在 RoPE 空间隔开文本末尾和首帧视觉 token。

TPS scaling 的口播方式也要简单：同样 10 个 token 在 16 FPS 和 30 FPS 里代表的真实时长不同， 所以需要用 \(\delta_t=TPS_{base}/TPS\) 映射到同一条物理时间轴。

6. 15 分钟压缩版讲法

  1. Slide 1-3：问题定位。Cosmos 3 解决 VLM、video generator、VLA/WAM 割裂的问题。
  2. Slide 4-5：任务统一。forward / inverse / policy 都是 clean/noisy token 布局。
  3. Slide 7-10：架构。AR Reasoner + DM Generator + MoT 双路径 attention。
  4. Slide 11-12：mRoPE。用 \((t,h,w)\) 和 TPS scaling 对齐 video/audio/action。
  5. Slide 14-16：训练推理。先理解，再生成，再动作；推理时 Reasoner、Generator、upsampler、action mode 分工。

压缩版结论：Cosmos 3 最值得学的不是模型规模，而是三层统一接口： token packing 统一任务，MoT 统一理解和生成，mRoPE 统一时空位置。

7. 结尾逐字稿

Cosmos 3 的核心不是“我有更多模态”，而是“我把不同 Physical AI 任务写成同一个 sequence contract”。 VLM 是 AR-only；视频生成是 text condition 加 noisy VAE token；forward dynamics 是 clean action 生成 future video； inverse dynamics 是 clean video 反推 action；policy 是 action 和 future video 共同 denoise。

对我们自己的 WAM 工作，最可复用的不是 Cosmos 3 的训练规模，而是这个设计思想： 先把 action 定义成状态转移，再用 clean/noisy token layout 学 action 和未来世界的对应关系。
