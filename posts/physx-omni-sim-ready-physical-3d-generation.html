Paper Reading · Simulation-Ready Assets

PhysX-Omni：从看起来像 3D，到真的能进模拟器

这篇的核心不是“单图生成一个更好看的 mesh”，而是把 3D 生成的目标从 visual asset 往 sim-ready physical asset 推了一步： 一个资产必须有 part、尺度、材料、affordance、运动学关系，并且能被 URDF/MJCF/XML 管线接进物理模拟。 PhysX-Omni 用 VLM 直接生成层级物理描述和高分辨率 part-level voxel，再借 TRELLIS 解码成 mesh，最后转成可模拟资产。

2026.05.23 阅读约 35 分钟 arXiv:2605.21572

0. 一句话结论

痛点：多数 image-to-3D / text-to-3D 方法只保证外观几何，缺真实尺度、材料参数、part 语义、运动关节和模拟器格式； 以前的 sim-ready 方法又常被限制在刚体、可变形或关节物体中的单一类型。 核心招：PhysX-Omni 把 Qwen2.5-VL 微调成一个物理资产生成器：先输出 object/part/group 的结构化物理描述， 再逐 part 生成 \(64^3\) voxel 的 template-based RLE 文本表示，随后用 TRELLIS decoder 还原 mesh，并用脚本写出 URDF/MJCF/XML。 效果：在 PhysXVerse/PhysX-Mobility 常规指标和 PhysX-Bench 上，物理属性、运动学和尺度明显优于 PhysX-Anything、PhysXGen、MonoArt、Articulate-Anything。 代价：训练重、依赖 VLM 和大量人工校验数据；benchmark 大量依赖 VLM judge 和渲染/仿真证据；复杂外观几何仍不是最强项。

不是
不是一个纯 3D reconstruction 模型，也不是一个纯机器人 policy 论文。
是
一个从单张图生成 simulation-ready object asset 的系统，目标是让生成物体能进入物理模拟和机器人训练。
核心 insight
sim-ready 资产的关键瓶颈不是 mesh 是否漂亮，而是对象是否被拆成可解释 part，并绑定了尺度、材料、affordance、运动学和模拟器 schema。

1. 论文定位

任务设定是 simulation-ready physical 3D generation from a single image。 输入是一张完整或局部遮挡的物体图片，输出不是单个静态 mesh，而是一组 part-level geometry、物理属性和运动学关系， 最终可以落到 URDF/MJCF/XML 这类模拟器可读表示。

路线 通常输出 问题 PhysX-Omni 的差异
通用 image-to-3D mesh / Gaussian / texture 外观看起来像，但缺质量、密度、关节、碰撞和尺度 直接生成物理属性和 part/group hierarchy
关节物体重建 articulated parts / joints 常只面向 articulated object，刚体/软体/室外大类覆盖弱 统一覆盖 rigid、deformable、articulated
PhysXGen / PhysX-Anything 物理属性 + 3D asset 几何表示受限，复杂 topology 和局部结构容易错 用 template-based RLE 直接建模高分辨率 voxel
MonoArt / Articulate-Anything 强几何或 articulation 物理属性维度不完整，材料/尺度/affordance 弱 在 PhysX-Bench 六维上统一评估并优化

因此它在论文谱系里的位置更接近“物理资产数据引擎”，而不是单个 generative model trick。 它把 VLM 当成结构化物理描述器和离散几何序列生成器，把 TRELLIS 当作后端 3D decoder，把 simulator 和 VLM judge 当成评估闭环。

2. 方法总览

Pipeline 是 coarse-to-fine、global-to-local。VLM 先读图并输出全局物理描述，然后围绕每个 part 生成 voxel RLE， decoder 把 voxel 转 mesh，最后脚本把 mesh、材料、尺度和运动学关系组织成模拟器资产。 

single RGB image
  -> Qwen2.5-VL physical understanding
  -> structured global description:
       Name / Category / Dimension
       Parts: l_i = material, density, Young's modulus, Poisson ratio, affordance rank, text description
       Group_info: part hierarchy + joint type A/B/C/D/CB/E + joint parameters
  -> for each part l_i:
       Qwen2.5-VL generates 64 x 64 x 64 voxel as template-based RLE text
  -> robust RLE parser:
       text -> runs_by_z -> voxel coords (N_i, 3)
  -> TRELLIS decoder:
       part voxel coords + condition image -> GLB/OBJ mesh per part
  -> asset converter:
       part mesh + physical metadata + joints -> URDF / MJCF / XML
  -> simulator / benchmark / robot policy learning

关键张量和对象：每个 part 的 voxel coordinate 是 \((N_i,3)\)，坐标落在 \(0 \ldots 63\) 的 grid 中； RLE 文本以 z-slice 为单位编码二维 mask；物理属性包括 density、Young's modulus、Poisson ratio、affordance rank； 运动学 group 用 A/B/C/D/CB/E 表达自由移动、滑动、绕轴旋转、绕点旋转、旋转加滑动、世界固定。

3. 关键创新点

创新点 1：把 3D geometry 变成 VLM 友好的 template-based RLE

旧方法为什么不行：直接让 VLM 输出 mesh vertices/faces 或 voxel index 序列会很长，且容易出现局部拓扑断裂。 3D VQ-GAN / latent token 可以压缩，但需要额外 codebook 或 special tokens，和现有 VLM vocabulary 不完全自然。

它怎么改：PhysX-Omni 先把 part voxel grid 沿 z 轴切成 64 张二值 mask。 每张 mask 先按二维 RLE 编码 occupied pixel runs；再引入 template layer，让相邻或相似 z-slice 共享模板，只记录增删差异。

\[ \mathrm{idx}(x,y)=x+W\cdot y,\qquad R_z=\{(s_k,\ell_k)\}_{k=1}^{K_z} \] \[ R_z = T_{a_z}\cup \Delta_z^+ - \Delta_z^- \]

这里 \(R_z\) 是第 \(z\) 层的 run list，\(T_{a_z}\) 是复用的模板层， \(\Delta_z^+\) 和 \(\Delta_z^-\) 分别是本层相对模板新增/删除的 runs。

为什么有效：它保留了显式几何结构，又让文本长度可控。 对平滑或重复结构，连续 z-slices 往往很相似；模板复用比逐层重复写完整 RLE 更省 token。 对 VLM 来说，这比随机散列的 voxel index 更像可预测的文本格式。

代价/限制：它仍是 \(64^3\) voxel，细节上限受 grid 限制；如果 VLM 输出格式错，后处理必须容错。 代码里确实写了 robust parser，说明生成文本会出现中文标点、括号错位、坏 run chunk 等噪声。

创新点 2：把“物理资产”作为结构化语言来生成

旧方法为什么不行：只生成 mesh 后再估计 physics metadata，容易出现语义与几何脱节： 轮子像轮子但不能转，门板和柜体没有 joint，材料参数无法解释仿真行为。

它怎么改：输出格式把 part、material、density、Young's modulus、Poisson ratio、affordance rank、basic description 和 group/joint 放在同一个结构里。 这让物体的功能、几何和运动学成为同一段 autoregressive 生成过程的一部分。

为什么有效：VLM 的强项是从图像和常识推断对象类别、part 功能和可动结构。 把这些信息先写进 structured description，再条件化 part voxel generation，可以减少“几何对了但功能错”的问题。

代价/限制：这里很多物理属性来自视觉常识和数据标注，而不是真实测量。 对透明材料、复合材料、隐藏关节、尺度缺参照物的图片，VLM 先验可能自信但不准。

创新点 3：PhysXVerse 补数据，PhysX-Bench 补评价

旧方法为什么不行：sim-ready 3D 数据太少，且评价常偏几何。 一个模型可以在 CLIP / render quality 上高分，却完全没有合理尺度、运动、材料和 affordance。

它怎么改：PhysXVerse 基于 PartVerse 等数据和 human-in-the-loop 流程扩展到 8.7K+ 高质量物理 3D assets， 覆盖 2.9K+ 语义类别，并带绝对尺度、材料、affordance、kinematics、function description。 PhysX-Bench 则用渲染图/视频作为证据，让开源 VLM judge 评估 geometry、absolute scale、material、affordance、kinematics、description 六维。

为什么有效：物理属性很多不是静态文本能判的。 材料要看 free fall / water drop 行为；运动学要看 articulation video；description 要看 part mask 是否对应语义。 这些证据比只喂 JSON 给 judge 更接近实际模拟使用场景。

代价/限制：benchmark 的可靠性依赖 VLM judge、渲染配置和仿真设置。 论文做人类一致性验证，但样本规模和 judge prompt 的敏感性仍是后续复现需要重点检查的地方。

4. 训练和推理流程

阶段 输入 操作 输出
数据预处理 part meshes + physical annotations 归一化 mesh，采样点云，voxelize 到 16/32/64 grid，转换 JSON 到 structured text part voxel npy + 结构化训练样本
VLM 微调 condition image + prompt + structured target Qwen2.5-VL-7B，5 epochs，max length 16384，bf16，Deepspeed zero3 能生成 basic_info 和每个 part 的 RLE voxel
推理 step 1 单图 1vlm_demo.py 先出 basic_info.txt，再逐 part 追问 voxel RLE ind_i.npy、allind.npy、可选 part PLY
推理 step 2 part voxel coords + condition image decoder_each.py 调 TrellisImageTo3DPipeline.run_decoder 每个 part 的 GLB/OBJ
推理 step 3 part meshes + basic_info + adjacency 3jsongen_update.py 推断连接区域、refine voxel、组织 XML/URDF/MJCF simulation-ready object asset
Benchmark 生成资产 渲染多视角图、part mask、kinematic video、material video，再交给 Qwen judge RQS/MCS/DCS/DQS/APS/KPS/MPS 等分数

训练细节：论文写使用 64 张 A100 约 14 天，peak learning rate \(2\times 10^{-5}\)，cosine decay，warmup ratio 0.03，有效 batch size 128。 代码中的 train_physx.sh 是 8 GPU 单节点模板，实际大规模训练需要多节点环境变量和数据路径配置。

5. 公式和算法拆解

算法 1：2D RLE over z-slices

每个 part 的 voxel 坐标是 \((x,y,z)\)。对固定 \(z\)，把二维 occupancy mask 展平：

\[ \mathrm{idx}(x,y)=x + 64y,\quad 0\le x,y<64 \]

连续占用区间被写成 \((start,length)\)。例如一层中 \([2013,2018]\) 连续占用，就写成 2013 6。 代码对应 encode_voxel_2drle_by_z() 和 decode_voxel_2drle_by_z()。

算法 2：template layer exact reconstruction

训练数据生成时，代码会找当前 slice 和已有模板的 run-set similarity。 如果相似度超过阈值，就复用模板并记录增删项；否则创建新模板。 

for z in 0..63:
    r = runs_of_slice[z]
    best_template = argmax similarity(r, template)
    if best_similarity < threshold:
        create new template T_a = r
        line: "z: layer a"
    else:
        adds = r - T_a
        removals = T_a - r
        line: "z: layer a +[adds] -[removals]"

这不是有损压缩。只要 parser 成功，\((T_a \cup adds) - removals\) 可以精确恢复每层 runs。 代码里还会 round-trip 检查 coords 与 coords_rec 的唯一 voxel index 是否相同。

公式 3：DQS 尺度评分

benchmark 里的 dimension score 是确定性后处理，不完全交给 VLM。 VLM 先从 condition image 估计真实物体最大尺度 \(v\)，算法输出生成物体最大尺度 \(g\)，代码计算 symmetric error：

\[ e=\frac{2|g-v|}{g+v},\qquad DQS = \begin{cases} 100(1-e/0.8), & e<0.8\\ 0, & e\ge 0.8 \end{cases} \]

这比简单绝对误差更适合不同尺度物体，但它仍依赖 VLM 对单图真实尺寸的先验估计。

算法 4：KPS/MPS 不是读参数，而是看模拟证据

KPS 让 judge 看 articulation video，判断可见 part 的先验运动一致性、隐藏后显露 part 的合理性、全局 articulation coherence。 MPS 让 judge 看 free-fall 和 water-drop video，结合 density、Young's modulus、Poisson ratio 判断材料行为。 这个设计避免了“数字看起来合理但仿真行为不合理”的假高分。

代码现实和论文叙述基本一致，但工程形态更像 research release： 数据路径需要手动改，训练脚本有集群环境变量假设，推理输出依赖多阶段文件约定。 好处是核心表示和 benchmark 都公开了，尤其 template RLE 的 encode/decode 可以直接复用。

9. 可复现清单

  • 环境：Python 3.10；Qwen2.5-VL；TRELLIS；flash-attn/xformers；spconv；kaolin；nvdiffrast；MuJoCo/Genesis/Blender 用于 benchmark。
  • 数据：下载 PhysXNet、PhysX-Mobility、PhysXVerse；按 repo 脚本生成 voxel、RLE text、25-view rendered condition images。
  • 训练：Qwen2.5-VL-7B-Instruct；5 epochs；lr \(2\times10^{-5}\)；warmup 0.03；effective batch size 128；max length 16384；bf16。
  • 表示：确认 template RLE round-trip 完全一致；检查空 part、run 越界、模板未定义、中文标点、坏括号。
  • 推理：先跑 1vlm_demo.py，再跑 2infer_geo.py，最后跑 3jsongen_update.py；每一步检查中间文件是否齐全。
  • benchmark：先跑 tiny smoke test，再分别跑 RQS/MCS/DCS/DQS/APS/KPS/MPS；注意 GPU、EGL、Blender、MuJoCo、Genesis 环境。
  • 人工校验：对尺度、材料、关节参数抽样做 simulator sanity check；不要只看 PhysX-Bench 总分。

【不确定】论文没有把 PhysXVerse 人工校验细则完全展开，也没有给出 VLM judge prompt sensitivity 的系统消融。 合理猜测：一是人类校验主要用于纠正 GPT 初标的明显物理错误；二是 PhysX-Bench 的 prompt 经过人工调优；三是 benchmark 样本可能偏向能渲染/能模拟的成功资产。 验证方式：抽样检查 dataset 原始 JSON、复跑 prompt 多 seed/多 judge、加入真实 simulator failure cases 看排名是否稳定。

10. 对 FastWAM / 具身操作的启发

如果你要做 WAM 或具身操作里的 one-shot task modeling，PhysX-Omni 的可迁移点不是整套 image-to-3D，而是它的 sim-ready object token schema。 一个任务执行样本里，action 不一定要先表示成低层关节轨迹；也可以先绑定到对象 part、affordance、joint 和可模拟物理属性。

改动点 预期收益 风险 验证实验
把 object state 表成 part-level schema：part id、material、affordance、joint type、scale one-shot demo 更容易抽出任务相关对象结构 VLM 先验错会污染 action abstraction 在开门/抽屉/按钮任务上比较 schema token vs raw image token 的 transfer
用 template RLE 或稀疏 voxel 表示可操作区域 比完整 mesh 轻，比纯语言 affordance 更可定位 64³ 分辨率可能不够精细接触 预测 grasp/contact heatmap，看分辨率和成功率关系
把 action 执行建模成 part joint parameter change 适合 one-shot 学“拉开”“旋转”“滑动”这类任务 非刚性接触和工具使用不易归纳为单 joint 比较 end-effector delta、latent action、joint-space intent 三种 action token
用 simulator evidence 评估生成的 action model 减少只看视觉预测的假进步 仿真资产本身误差会影响结论 同一 demo 在真实标注资产和生成资产上分别 rollout policy

11. 速读备忘卡

  • PhysX-Omni 的目标是 sim-ready physical 3D asset，不是只生成漂亮 mesh。
  • 它覆盖 rigid、deformable、articulated 三类对象。
  • VLM 先生成全局结构化物理描述，再逐 part 生成 voxel geometry。
  • template-based RLE 是核心表示：z-slice 2D RLE + template layer + add/remove residual。
  • 这个表示不引入 special tokens，能直接放进 Qwen2.5-VL 的文本生成空间。
  • PhysXVerse 是 8.7K+ sim-ready assets，覆盖 2.9K+ 类别和五类物理注释。
  • PhysX-Bench 评估六维：geometry、absolute scale、material、affordance、kinematics、description。
  • DQS 是确定性 symmetric error 分数；MPS/KPS 依赖仿真视频证据和 VLM judge。
  • 实验显示 PhysX-Omni 的物理属性和运动学明显强，但纯几何外观不是所有指标最优。
  • 代码公开了训练/推理/benchmark 主流程，但数据路径和集群训练需要较多手工配置。
  • 对具身操作最有用的 insight：把任务相关对象建成 part + joint + affordance + physical metadata，而不是只用 RGB latent。
