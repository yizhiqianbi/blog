γ-World：多人 world model 需要交换对称的 agent 轴

这篇论文的核心不是“把多个玩家画面拼成一个大视频”，而是给 video world model 明确加上 agent 轴、交换对称的身份编码和低成本的跨 agent 通信通道。 它回答的是多人 world model 的一个根问题：多个可控主体共享同一个世界时，模型怎样既区分“你我”，又不把“1 号位/2 号位”写死。

2026.06.15 阅读约 40 分钟 arXiv:2605.28816

0. 一句话结论

痛点：单人 interactive video world model 只要跟随一条 action stream；多人场景还要保证多个视角、多个动作、同一个共享世界之间一致。 核心招：γ-World 把多人输入组织成 \(P\times T\times H\times W\) 的 agent-time-space latent，用 Simplex Rotary Agent Encoding 给 agent 做无参数、交换对称的身份编码，再用 Sparse Hub Attention 让 agent 通过少量 hub tokens 通信。 效果：在多人 Minecraft 评测上，γ-World 在 Memory/Grounding/Movement/Building/Consistency 五类任务的 FVD/FID 都明显优于 Frame concat 和 Solaris；并用 causal student + KV cache 做到 24 FPS streaming rollout。 代价：实现依赖大模型、大算力和蒸馏流程；代码尚未释放；hub 是通信瓶颈，能不能承载复杂多人策略和长程物理仍要更强验证。

这篇到底在解决什么
它解决的是多人生成式 world model 的 agent identity 和 cross-agent communication 问题。不是“生成更清楚的视频”，而是让多个独立可控 agent 在同一个生成世界里互相看见、互相影响，并且可扩到超过两个玩家。
核心 insight
多人世界里的 agent 是 exchangeable entities：同能力玩家不该因为占了 slot 1 或 slot 2 被模型区别对待。身份编码应该“可区分但不偏置槽位”，通信也不该是所有 token 两两全连。
和 MultiGen 的关系
MultiGen 的核心是外部 shared memory；γ-World 的核心是把 shared world consistency 做进 transformer 的 agent 轴、RoPE 和 attention mask。一个偏显式状态，一个偏 neural token topology。

1. 论文定位

γ-World 属于 action-conditioned multi-agent video world model。 输入是多个 agent 的历史观察和动作，输出是每个 agent 下一步或未来一段观察。 它不是强化学习里的 compact latent dynamics，也不是传统游戏引擎；它是把 video diffusion transformer 当成视觉模拟器，再补上多人一致性的结构。

\[ \gamma\text{-World}\left(\{o^p_{1:t}\}_{p=1}^{P}, \{a^p_{1:t}\}_{p=1}^{P}\right) \rightarrow \{o^p_{t+1}\}_{p=1}^{P} \]

这里 \(P\) 是 agent 数，\(o^p_t\) 是第 \(p\) 个 agent 在时间 \(t\) 看到的图像，\(a^p_t\) 是它的动作。 关键假设是：\(\{o^p_t\}_{p=1}^{P}\) 不是互不相关的视频，而是同一个 underlying world state 的不同视角。

范式 典型做法 瓶颈 γ-World 的差异
Single-agent world model 一条 action stream 控制一个观察流 没有跨视角一致性约束 显式建模 \(P\) 个 agent 的同步 observation/action
Frame / spatial concat 把多玩家视角拼成大画布 玩家数变动会改变分辨率和 token 组织 Sequence concat，保留每个 agent 独立 stream
Solaris 多人 Minecraft + learned player ID + dense joint attention ID 绑定固定 slot，dense attention 随 agent 数二次增长 Simplex RoPE 身份 + Sparse Hub Attention
MultiGen 显式 map/pose memory 维护共享世界 依赖可读写的外部状态结构 把共享一致性压进 token 拓扑和 attention 结构

2. 方法总览

γ-World 的 pipeline 可以压缩成五步：

  1. 收集同步多人轨迹：每个时间步有 \(P\) 个 agent 的观察 \(o^p_t\) 和动作 \(a^p_t\)。
  2. 视觉 tokenization：把未来视频表示成 latent \(Z_0\in\mathbb{R}^{P\times T\times H\times W\times C_z}\)。
  3. 动作注入：共享 action encoder 把 \(a^p_t\) 映射到 \(u^p_t\in\mathbb{R}^{D}\)，作为每层 transformer token 的 bias。
  4. 多人 DiT：用 4D RoPE 编码 \(t,p,h,w\)，其中 agent 轴用 regular simplex 的顶点做相位。
  5. 实时 rollout：先训 bidirectional teacher，再训 causal student，最后用 conditional Self-Forcing + DMD 蒸馏成 few-step causal generator，推理时按 block 生成并维护 KV cache。
per-agent observations/actions
  -> visual tokenizer: Z0 in R^{P x T x H x W x Cz}
  -> shared action encoder: u_t^p in R^D
  -> causal multi-agent DiT
       -> 4D RoPE(t, p, h, w)
       -> Simplex Rotary Agent Encoding on p
       -> Sparse Hub Attention for cross-agent messages
  -> future rollouts for every agent
  -> streaming with agent KV caches + shared hub KV cache

3. 关键创新点

创新 1：把 agent identity 从 learned slot 改成 simplex RoPE

旧方法为什么不行：如果用 learned player embedding，slot 1 和 slot 2 会变成有语义差别的位置。 这违背多人世界的交换性：两个同能力玩家对调编号，世界规律不应该变。 如果用线性 agent index \(p\omega\)，agent 1-2、1-4、2-4 的距离也不同，本质上还是给 slot 排了序。

它怎么改：γ-World 把 agent 放在 regular simplex 的顶点上。所有顶点到顶点的距离相同，所以任意两个 agent 的相对身份距离等价。

\[ s_v=\sqrt{\frac{V}{V-1}}\ Q\left(e_v-\frac{1}{V}\mathbf{1}\right),\quad \lVert s_v\rVert^2=1,\quad \lVert s_v-s_{v'}\rVert^2_2=\frac{2V}{V-1} \]

\(V\) 是 simplex pool size，\(e_v\) 是第 \(v\) 个 one-hot，\(Q\) 把零均值子空间等距嵌入到 agent-angle space。 一个 batch 里只有 \(P\le V\) 个 active agents，训练时随机采样 injective assignment \(\pi\)，把 agent \(p\) 分到顶点 \(s_{\pi(p)}\)。

\[ \theta_p=\alpha s_{\pi(p)},\qquad R_{\text{simp-4D}}(t,p,h,w)= \operatorname{diag}\left(R_t(t),R_{\text{simp}}(\pi(p)),R_h(h),R_w(w)\right) \]

为什么有效：它同时满足两个目标：每个 agent 有不同 phase，模型能区分“这个动作是谁发的”；所有 agent pair 又等距，模型不会偏爱固定 slot。 这就是它能从 2-agent 训练 zero-shot 激活到 4-agent inference 的结构基础。

代价/限制：它支持的最大 agent 数受 simplex pool 和 agent rotary band 限制，论文给出 \(V\le d_p/2+1\)。非常大规模群体可能需要更大的 agent band 或层级分组。

实现细节：Appendix 写得很具体：模型把 head rotary dimension 分成 \((64,32,16,16)\)，分别对应 \((t,p,h,w)\)；simplex pool size 为 4，训练时只有 2 个 active runtime slots，每步随机采样 2 个顶点并打乱 slot 顺序。

创新 2：用 Sparse Hub Attention 替代 dense all-to-all cross-agent attention

旧方法为什么不行：dense joint attention 会让每个 agent token 直接看所有其他 agent token。 设每帧空间 token 数为 \(L=HW\)，block 长度为 \(n\)，agent 数为 \(P\)，cross-agent attention 成本是 \(\mathcal{O}(P^2 n^2 L^2)\)。超过两个玩家后，这个成本很快吞掉实时性。

它怎么改：γ-World 加 \(K\) 个 learnable hub tokens。agent token 只能看自己 stream 和 hub；hub 可以看所有 agent 和其他 hub。 不同 agent 之间没有直接 attention，只能走两跳路径：agent -> hub -> agent。

\[ \mathcal{M}_{hub}(i,j)= \mathbf{1}\left[\rho(i)=\rho(j)\ \vee\ \rho(i)=hub\ \vee\ \rho(j)=hub\right] \]
\[ \mathcal{M}(i,j)=\mathbf{1}[b(j)\le b(i)]\cdot \mathcal{M}_{hub}(i,j) \]

\(\rho(i)\) 表示 token 属于哪个 agent 或 hub，\(b(i)\) 是 temporal block index。 第一项保证 block-causal，第二项保证跨 agent 信息只能通过 hub。

\[ \mathcal{O}(P n L(nL+nK))+\mathcal{O}(nK(PnL+nK)) \]

固定 \(n,L,K\) 后，这个复杂度对 \(P\) 近似线性。 Hub tokens 在输出前丢掉，只作为内部 shared communication state。

为什么有效：多人交互不一定需要每层每个 pixel token 对所有其他玩家 pixel token 做全连接。 许多互动可以被压成“谁在哪、做了什么、共享对象发生了什么”的紧凑状态。Hub 就是这种 neural blackboard。

代价/限制：hub 是瓶颈。K 太小会丢交互信息；K 太大又回到高成本。论文选 \(K=8\) 是工程折中，不是理论最优。

创新 3：把高质量 bidirectional diffusion 蒸馏成 causal streaming student

旧方法为什么不行：bidirectional DiT 能看完整未来视频，质量好，但不能在线交互；causal model 可以流式生成，但只用 teacher forcing 训练会遇到 train-test mismatch，长 rollout 时误差累积。

它怎么改：三阶段训练：先训练 full-context bidirectional teacher；再训练 block-causal multi-step student；最后用 Conditional Self-Forcing + DMD 把 student 蒸馏成 4-step few-step generator。

为什么有效：teacher 提供高质量条件分布，causal student 学会只看过去，distillation 让模型在自己生成的历史上继续训练，推理时 distribution mismatch 更小。

实现细节：蒸馏时每个 block 用 timesteps \(\{1000,750,500,250\}\)，flow shift 为 5.0；生成后的 block 会重新以 context-noise level 128 前向一次，写入每层 KV cache。 generator/critic 交替比例为 1:4，总共 400 iterations。

4. 训练和推理流程

输入和输出

阶段 输入 输出 关键约束
Teacher training 完整 \(P\)-agent video latent、initial observations、per-agent actions velocity field / denoised latent dense bidirectional attention，质量优先
Causal student pretraining block-wise noised latent、actions、past blocks autoregressive diffusion rollout block-causal mask + Sparse Hub Attention
Self-Forcing distillation student 自己生成的历史、teacher conditional score few-step causal generator rollout-aware，减少 exposure bias
Inference first frames + latest action block + KV cache 每个 agent 的未来视觉 latent/video 4-step denoise，24 latent-frame rolling window，24 FPS

动作格式

游戏域每帧每个 agent 有 25 维 action：23 个离散玩家控制和 2 个连续 camera 控制。 离散项包括 inventory、ESC、hotbar.1-9、forward/back/left/right、jump/sneak/sprint、swapHands、attack/use/pickItem/drop。 连续项是 cameraX/cameraY。

机器人域每帧每个 robot 有 10 维连续 action：3D end-effector position、6D orientation、gripper opening。 论文把左右机械臂看成两个 interacting agents。

模型规模和训练设置

  • Backbone：Cosmos-Predict2.5-2B TI2V checkpoint。
  • Transformer：hidden dimension \(D=2048\)，28 blocks，16 heads，head dim 128，MLP ratio 4，AdaLN-LoRA rank 256。
  • 训练分辨率：2-agent gameplay，320×480 per view。
  • Teacher：93-frame clips / latent length 24 训练 10k iterations，再用 189-frame clips / latent length 48 fine-tune 6k。
  • Causal student：93-frame clips 训练 15k iterations。
  • Optimizer：AdamW，LR \(3\times10^{-5}\)，weight decay \(10^{-3}\)，\((\beta_1,\beta_2)=(0.0,0.999)\)，100-step warmup，gradient clipping 0.1。
  • 算力：teacher 和 student 都使用 32 NVIDIA GB200s。这个成本是复现门槛。
  • Inference：不使用 CFG，论文说 unguided sampling 经验上更准确。

5. 公式逐行讲解

公式 1：flow matching 目标

\[ z_{\sigma}=(1-\sigma)z_0+\sigma\epsilon,\qquad \mathcal{L}_{FM}= \mathbb{E}_{z_0,\epsilon,\sigma} \left[\lVert v_{\theta}(z_{\sigma},\sigma,\mathcal{C})-(\epsilon-z_0)\rVert_2^2\right] \]

\(z_0\) 是 clean video latent，\(\epsilon\sim\mathcal{N}(0,I)\) 是噪声，\(\sigma\in[0,1]\) 是 noise level。 \(v_\theta\) 预测从 clean 到 noise 的 velocity，\(\mathcal{C}\) 包括 initial observations 和 per-agent actions。 实现上就是 DiT 在 noised latent 上回归 velocity。

公式 2：多 agent latent 形状

\[ Z_0\in\mathbb{R}^{P\times T\times H\times W\times C_z} \]

这是整篇最重要的 shape。 相比单人 video latent \(T\times H\times W\times C_z\)，它增加了显式 agent axis。 这让“哪个 token 属于哪个 agent”成为模型结构的一部分，而不是拼图后的隐含信息。

公式 3：动作注入

\[ u^p_t=f_a(a^p_t)\in\mathbb{R}^{D},\qquad \beta^p_{\ell,t}=g_{\ell}(u^p_t)\in\mathbb{R}^{D} \]
\[ x_{\ell,p,t,h,w}\leftarrow x_{\ell,p,t,h,w}+\beta^p_{\ell,t} \]

\(f_a\) 是共享 action encoder，所有 agent 共用同一套参数；\(g_\ell\) 是每层 action projection。 \(\beta^p_{\ell,t}\) 被 broadcast 到该 agent、该时间步的所有 spatial tokens。 这样同一个动作在不同 agent 上有同样表示，身份差异交给 simplex RoPE，而不是交给 action encoder。

公式 4：Simplex agent rotation

\[ R_{4D}(t,p,h,w)=\operatorname{diag}(R_t(t),R_p(p),R_h(h),R_w(w)) \]

普通 3D RoPE 只有 \(t,h,w\)。γ-World 加了 \(p\)，并把 \(R_p(p)\) 换成 \(R_{\text{simp}}(\pi(p))\)。 这相当于给每个 agent 一个相位，但这些相位来自 simplex 顶点，天然等距。

公式 5：Hub attention mask

\[ \mathcal{M}(i,j)=\mathbf{1}[b(j)\le b(i)] \cdot \mathbf{1}[\rho(i)=\rho(j)\vee \rho(i)=hub\vee \rho(j)=hub] \]

这个 mask 同时做两件事：时间上不能看未来 block；agent 上不能直接看其他 agent，只能看自己和 hub。 推理时也维护相同拓扑：每个 agent 有自己的 KV cache，hub 有共享 KV cache。

隐藏 confound

  • 对比 Solaris 时，具体训练数据、模型容量、算力是否完全对齐不够透明；论文更像“系统设计胜出”，不是严格同参公平赛。
  • 定量主要在 Minecraft-style 游戏上，真实机器人部分更多是 qualitative demo。
  • FVD/FID 衡量视频分布质量，不等于策略一致性或可用于规划的状态正确性。
  • zero-shot 2-to-4 的论据很有价值，但 pool size 已经设为 4；它不是无限扩 agent。

8. 可复现清单

代码现实：GitHub 仓库截至 2026-06-15 只有 README 和 assets。README 明确写了 code、distilled streaming checkpoints、training scripts、dataset preparation tools 都是 coming soon / planned。 所以下面是论文和 appendix 能确认的复现要点，不是代码级复现。

  • 需要 Cosmos-Predict2.5-2B TI2V 初始化权重。
  • 需要同步多人数据：每个时间步对齐 \(P\) 个 agent 的 video/action。
  • 训练时至少要实现 sequence concat，而不是 spatial concat。
  • RoPE head partition 使用 \((64,32,16,16)\)，对应 \((t,p,h,w)\)。
  • simplex pool size 4；2-agent 训练时随机抽两个顶点并 permute slot。
  • action encoder 需要共享参数，避免把 agent identity 泄漏进 action branch。
  • Sparse Hub Attention 默认 \(K=8\) hub tokens per latent frame。
  • causal student 需要 local attention window，论文为最近 24 latent frames per view。
  • distillation 要按 rollout 写 KV cache，否则训练和推理仍不一致。
  • 论文没有释放数据生成脚本，Minecraft bot 脚本、动作同步、episode taxonomy 都是复现风险点。

【不确定】RealOmin-Open 的具体数据预处理、camera/action 对齐频率、机器人视频分辨率没有在正文里展开。 合理猜测有三种：一是按原数据集频率直接重采样；二是对齐到 Cosmos latent temporal stride；三是只做短片段 qualitative。 验证方式：等代码/data prep release，或检查未来仓库里的 robot preprocessing scripts。

9. 对 FastWAM / UE 多人数据集的启发

如果你要做 UE 多人 world model 数据集，这篇比 MultiGen 更接近“多人 agent 轴怎么设计”。 它的可搬运点不是 Minecraft，而是三条结构原则。

γ-World 设计 在 UE 数据集里对应什么 对 FastWAM 的意义
显式 agent axis 每个 pawn/NPC/player 一条同步 observation/action/state stream 不要把多人数据拼成单视频；保留 agent 维度
Simplex identity 同类 bot 共享能力，不绑定 Player1/Player2 固定语义 支持 one checkpoint 泛化到不同 agent count/order
Sparse hub 共享黑板：目标点、敌我位置、关键物体、zone 控制、事件摘要 把多人交互压成 shared latent，而不是 all-to-all token 暴力交互
per-agent action trace BT/StateTree decision、nav target、look yaw/pitch、fire/use、skill id、delta pose 没有人类键鼠 action 时，也要定义可学习的 agent control interface
2-agent train, 4-agent test 先做小规模 capture/pursuit，再测试更多 bot 可以把 scalability 变成 proposal 的核心实验

对 FastWAM，我会把这篇转成一个表示设计建议： world latent 不只是一段视频 latent，而应该有 shape 类似 \(Z\in\mathbb{R}^{P\times T\times N\times D}\)，其中 \(P\) 是 exchangeable agent axis，\(N\) 是每个 agent 的视觉/状态 tokens。 跨 agent 通信走 hub tokens，hub 可以显式接 UE shared state，也可以纯 neural learnable。

如果没有底层 action，可以先定义 proxy action： 

agent action at t =
  behavior_tree_node_id
  + high_level_intent_id
  + nav_target_delta
  + look_delta
  + weapon/use/skill command
  + compact physical delta pose

这里的 action 不一定是玩家键鼠输入；它可以是 AI 控制栈对 pawn 发出的可执行控制。 关键是每个 agent 的 action 必须同步、可复现、可用于条件生成。

10. 改进方向

  1. 层级 hub tokens ->把 squad/team/scene/event 分成不同 hub；预期收益是支持 8+ 或 16+ agent；风险是 routing 变复杂；实验用 2/4/8/16 agent scaling curve。
  2. 显式 shared state + neural hub 混合 ->把 MultiGen 式 map/pose memory 接到 γ-World hub；预期收益是长程一致性更强；风险是工程接口变重；实验比较无 memory、纯 hub、hub+map。
  3. 异构 agent encoding ->在 simplex identity 外加 role/type embedding；预期收益是支持玩家、NPC、车辆、机器人混合；风险是破坏交换对称；实验做同类交换不变性和异类可区分性测试。
  4. 任务级 action abstraction ->把键鼠 action 换成 intent/action chunk；预期收益是更适合机器人和 UE AI；风险是丢低层控制细节；实验比较 raw action、delta pose、BT intent 三种条件。
  5. 规划可用评测 ->不只看 FVD/FID，而测 rollout 是否能支持 agent 选择动作；预期收益是接近 world model 本义；风险是需要 closed-loop eval；实验用生成未来做 MPC/BT lookahead。
  6. 长程 memory benchmark ->构造离开视野后再相遇、建筑被修改后回访、多人协作搬运；预期收益是测 shared state 而不是短视频质量；风险是数据采集更复杂。

11. 速读备忘卡

  • γ-World 的核心是多人 world model 的 agent identity 和 communication 设计。
  • 不要把多玩家视角拼成大图；保留 \(P\times T\times H\times W\) 的 agent axis。
  • Simplex RoPE：agent 是 regular simplex 顶点，彼此等距，交换对称。
  • 训练时用 pool size 4，但只激活 2 个 agent，并随机抽顶点和打乱 slot。
  • Sparse Hub Attention：agent 不直接互看，信息走 agent -> hub -> agent。
  • Cross-agent attention 从 \(\mathcal{O}(P^2)\) 变成近似 \(\mathcal{O}(P)\)。
  • 部署靠 bidirectional teacher -> causal student -> conditional Self-Forcing distillation。
  • 实时推理维护每个 agent 的 KV cache 和共享 hub KV cache，论文报告 24 FPS。
  • 主表中 γ-World 在五类 Minecraft 多人任务 FVD/FID 都优于 Solaris。
  • 代码截至 2026-06-15 尚未释放，复现只能依据论文 appendix。
  • 对 UE/FastWAM：重点是同步 per-agent stream、exchangeable agent encoding、shared hub/blackboard。
