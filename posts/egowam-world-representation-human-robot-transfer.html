EgoWAM：人类视频如何通过“世界变化”迁移给机器人

动作是 embodiment-specific 的：人的手、头部相机和行为风格不能直接复制给机器人。场景变化却更容易共享。EgoWAM 的实验核心，是固定同一套策略骨干与动作头，只替换未来预测目标，回答 Pixel、DINO feature 与相机稳定 3D Flow 中谁更适合做人机迁移接口。

2026.07.18 分类：robotics-world-models 论文日期：2026.07.08 PDF HTML Project

0. 一句话结论 #

EgoWAM 发现，人类 ego 数据若只通过对齐后的 action loss 进入策略，动作风格和形态差异会造成负迁移；增加一个训练期未来预测通道后，人类数据可以通过场景动力学塑造共享 trunk，其中 DINO feature 最利于新物体/新场景泛化，相机稳定 3D Flow 最利于空间精度，代价是额外的 teacher、world head 和离线 3D tracking，而推理时 world head 可完全删除。

核心 insight：人类数据不是“不够像机器人”所以没用，而是 action decoder 这个迁移接口选错了。动作描述“这个身体怎么动”，世界表征描述“环境发生了什么”；后者更接近 embodiment-invariant supervision。

1. 论文定位：研究 world target，而不是追求更强生成画质 #

任务是双臂机器人策略的人机联合训练。数据有两种 embodiment：

$$ \mathcal D_H=\{(o_t^H,a_t^H)\}_{t=1}^{N_H},\qquad \mathcal D_R=\{(o_t^R,a_t^R)\}_{t=1}^{N_R}. $$

BC baseline 已尽量把两者对齐到同一个 14D EEF action space，再共同训练 action flow head。EgoWAM 在此基础上增加未来预测头，但固定 trunk、action head 与数据 mixture，只改变 world target。

它与 Fast-WAM 的共同点是把世界预测当作训练期 representation shaping，而非部署时先想象未来再读出动作。更严格地看，它的联合分布被写成两个并行 readout：

$$ p_{\theta,\psi}(a_{t:t+k},s_{t+T}\mid o_t) =p_\psi(s_{t+T}\mid z_t)\,p_\theta(a_{t:t+k}\mid z_t), \quad z_t=f_\phi(o_t). $$

注意 $p_\psi(s_{t+T}\mid z_t)$ 没有显式条件于 $a$。因此它不是可回答“如果执行动作 A/B，未来分别怎样”的 action-conditioned simulator，而是共享当前表示上的 future-prediction auxiliary task。称为 WAM 没问题，但能力边界要分清。

3. 关键创新点 #

3.1 先把 action channel 对齐到足够强，再证明它仍然不够

旧方法为什么不行：如果 human action 与 robot action 连坐标系都不同，那么 BC 输给 WAM 没有意义。作者先构造尽可能强的 action-level baseline。

每条轨迹都写成双臂 14D：每臂 6-DoF EEF pose 加 1D gripper。机器人由 joint angle 经 FK 得到 EEF，并放到静态 ego camera frame；人手位姿原本在移动 Aria device frame 中，重新表达为当前时刻 $t$ 的相机坐标：

$$ a^H_{t:t+k}=left[ (T_t^{device})^{-1}T_{t+i}^{device}p^H_{t+i} \right]_{i=1}^{k}. $$

这样头部转动不会直接变成手部动作。速度仍不同：人类用 1.0 s 窗口，机器人用 1.5 s 窗口，但都重采样成 $k=100$ 步，按“任务进度”而不是物理时间对齐。每维 1%/99% 分位映射到 $[-1,1]$，降低手部追踪 outlier 的影响。

结果：即便做完坐标、速度与数值范围对齐，自然 human action 仍可能来自不同抓法、不同身体形态和不同风格。BC 仍会学到机器人不可执行的动作。这说明 residual embodiment gap 不是简单归一化可以消掉的。

3.2 World channel：让人类数据通过“effect”监督 trunk

BC 目标是：

$$ \mathcal L_{BC}=\mathcal L_{CFM}^{robot}+\mathcal L_{CFM}^{human}. $$

EgoWAM 增加两种 embodiment 的 world loss：

$$ \mathcal L_{EgoWAM}= \underbrace{\mathcal L_{action}^{robot}+\mathcal L_{action}^{human}}_{\mathcal L_{action}} +\lambda\underbrace{(\mathcal L_{world}^{robot}+\mathcal L_{world}^{human})}_{\mathcal L_{world}}, \qquad \lambda=1. $$

为什么有效：人手与夹爪打开同一个袋子的动作轨迹不同，但“袋口从闭合变为打开”相同。world loss 给共享 trunk 一条不经过 action decoder 的梯度路径，迫使人类与机器人观测围绕共同物理 effect 聚合。UMAP 中 BC 的人机 embedding 分离，而 3D-Flow WAM 更接近共享空间。

重要边界：full EgoWAM 并没有丢掉 human action label。附录的 `Flow-only` 消融表明，仅 world supervision 已优于仅 action supervision；但 Action + Flow 在所有 split 上最好，且 flow loss 从 human/robot 的 0.23/0.20 降到 0.22/0.19。动作梯度仍能提供 task relevance，只是不再是唯一接口。

3.3 三种 future target：Pixel、DINO、3D Flow

Target保留什么丢掉什么主要问题
Pixel VAE纹理、颜色、布局、运动很少把手/机器人外观、背景和 ego-motion 一起监督
DINO feature物体语义、形状与 patch correspondence部分低层纹理仍在 image grid 上，头动会改变空间位置
3D Flow相机稳定后的物理位移外观和静态背景依赖 3D tracker/VIO，语义弱、预处理重

Pixel：画面越真，不等于物理状态越对

Pixel 将未来 ego frame 编进冻结 Wan VAE，得到 $16\times16\times16$ latent。轻量 Pixel head 是 6-block 384D DiT；Pixel-PT 则用预训练 VACE-1.3B，30 层、1536D。两者都做噪声/速度预测。

Pixel-PT 在 bag-grocery 上出现一个典型失败：预训练视频先验倾向于“袋子通常是打开的”，于是尚未抓袋口就生成已打开的未来，policy 提前进入放物阶段。它生成更清晰，却比从头训练的模糊 Pixel 更不 faithful。world representation 的标准应是因果状态保真，不是感知画质。

DINO：语义抽象带来 OOD 泛化

DINO target 是冻结 DINOv2-B 的 future patch map，去掉 CLS/register token 并逐 token LayerNorm，形状为 $768\times16\times16$。head 使用 RAE 的 $\mathrm{DiT}^{DH}$ 思路：6-block 384D backbone 加 2-block 2048D wide head。宽 head 是必要的，因为 semantic latent channel 768 已远大于普通 VAE latent。

DINO 抑制颜色和纹理差异，又保留物体身份和结构，因此在 unseen object / unseen scene 上最好；但 patch 仍绑定图像坐标，人类头部转动会使同一物体落在不同位置，D3 只部分满足。

3D Flow：把头动从世界变化里减掉

Track4World 估计每像素 3D point track。若直接做 $X_{t+T}-X_t$，静止背景也会因人头转动产生巨大 flow。作者使用 Aria VIO pose，把未来点先变回时刻 $t$ 的相机坐标：

$$ \widetilde X_{t+T}=(T_t^{cam})^{-1}T_{t+T}^{cam}X_{t+T}, \qquad F_{[t,t+T]}=\widetilde X_{t+T}-X_t. $$

稳定后，静态背景接近零，物体被移动才产生非零位移。head 在当前图像均匀取 $28\times40=1120$ 个 anchor，预测 $100\times1120\times3$ flow tensor；小于 2 mm（机器人）或 10 mm（人类）的位移被过滤，人类 clip 还跳过头尾各 20 帧。

为什么有效：它同时满足 appearance abstraction、cross-embodiment consistency、ego-motion factoring。代价是离线数据管线需要可靠相机姿态和 dense 3D tracking，tracker 的深度/遮挡误差会直接成为监督噪声。

4. 训练和推理流程 #

训练输入

  • Human：当前 Aria ego RGB、14D 手部 action chunk、对应 future ego frame 或 3D tracks。
  • Robot：当前 Aria ego RGB、两路 wrist RGB、14D proprio、14D EEF action chunk、future target。
  • 每步同时采 32 个 robot 与 32 个 human 样本；observation horizon 只有 1 帧。

单步训练

  1. 模态/本体专属 stem 把输入投到共享 256D token space。
  2. 64 action tokens 与 16 future tokens 和 observation tokens 一起经过 HPT trunk。
  3. action CrossTransformer 对 $[B,100,14]$ noisy chunk 做 conditional flow matching。
  4. world head 对 Pixel/DINO/3D Flow target 做 diffusion/flow objective。
  5. 四项人机 loss 以 $\lambda=1$ 联合更新 stems、trunk 与对应 heads。

推理

  1. 只读取当前一帧 ego/wrist image 与 14D proprio。
  2. world head 不运行，future target、Track4World、DINO 与 VAE 都不需要。
  3. action head 用 50 个 v-prediction Euler steps 解码 100×14 chunk。
  4. 策略在单张 RTX 4090 上以 30 Hz 对接 ARX5 控制环。

因此 3D Flow 的 100×1120×3 大张量只增加训练与数据预处理成本，不增加真机 inference footprint。

5. 关键公式与张量实现 #

5.1 Action flow matching

$$ a^\tau=(1-\tau)\epsilon+\tau a,\qquad \epsilon\sim\mathcal N(0,I),\quad \tau\sim\mathrm{Beta}(1.5,1.0). $$

$a\in\mathbb R^{B\times100\times14}$ 是 clean action，$\epsilon$ 同形状。这里 $\tau=0$ 为 noise，$\tau=1$ 为 data；Beta(1.5,1.0) 更偏向 clean 端。CrossTransformer 交替 self-attention 和对 trunk 的 cross-attention，预测 velocity，50 步积分恢复 action。

5.2 Pixel / DINO 共用线性噪声路径

$$ s^\tau=(1-\tau)\epsilon+\tau s,\qquad \mathcal L_{world}=\mathbb E\|\epsilon-\epsilon_\psi(s^\tau,\tau,f_\phi(o))\|_2^2. $$

Pixel 的 $s\in\mathbb R^{B\times16\times16\times16}$；DINO 的 $s\in\mathbb R^{B\times768\times16\times16}$。公式相同，target geometry 与 decoder capacity 完全不同，因此“只换表征”的说法应理解为只改变 world branch，不能理解为同一个 head 输入不同 target。【不确定】正文公式写的是 $\epsilon$-prediction，附录却称 Pixel/DINO 使用 $v$-prediction；在 policy code 发布前无法确认实现采用哪种 parameterization，复现时应以训练 target 构造函数和 sampler 更新式交叉核对。

5.3 3D Flow velocity

$$ \mathcal L_{world}^{Flow}=\mathbb E\left\| u_\psi(s^\tau,\tau,f_\phi(o),q)-(s_q-\epsilon_q) \right\|_2^2. $$

$q\in\mathbb R^{1120\times3}$ 表示当前 frame 的 anchor 3D 位置，$s_q\in\mathbb R^{100\times1120\times3}$ 是这些 anchor 在 horizon 内的相机稳定位移。4-block、256D decoder 同时条件于 $q$ 和 trunk features。

最有说服力的反事实：故意把 human action 搞得不可执行

在 bag-grocery 中，作者另采一批故意使用异常抓法、头动更大的 human demonstrations。BC 从 robot-only 的 40% 掉到 20%；3D Flow WAM 在 misaligned data 下仍达到 75%。这比只比较平均分更直接地支持论文机制：action channel 会传递风格错配，world channel 对这种错配更鲁棒。

证据强弱

  • 强证据：同 backbone/action/data 下三类 world branch 的真机对比；misaligned/aligned human 反事实；world-only 与 action+world modality ablation。
  • 重要 confound：target 变化时 head 也变化。Pixel 是 6×384 DiT，DINO 多一个 2×2048 wide head，3D Flow 是 4×256 decoder，Pixel-PT 更是 1.3B。结果不能完全归因于 target representation。
  • 训练预算不完全相同：Pixel-PT 用 2×L40S、1000 epochs；其他方法 1×L40S、2000 epochs。作者控制了 wall-clock 约两天，但没有控制 samples、parameters 和 FLOPs。
  • 策略泛化范围有限：每任务一套 policy，不是多任务 foundation policy；作者明确承认尚不能从 human data 学会新的 motion primitive。
  • 模拟器外推较弱：RoboTwin 跨本体 transfer 在三个任务上的 success 大多为 0–28%，说明这个接口还没有被证明能稳定跨机器人扩展。
  • 统计仍较粗：每个 split 20 次 rollout，一个成功样本就是 5 个百分点；置信区间处理规范，但细小差异仍不能过度解释。

10. 速读备忘卡 #

  • EgoWAM 研究的是 human-to-robot co-training 的 world representation。
  • BC 只有 action transfer channel，残余形态与行为风格会造成负迁移。
  • human/robot action 已对齐到 100×14 EEF chunk，baseline 不是故意做弱。
  • HPT trunk 是 256D、16 blocks，使用 64 action tokens 与 16 future tokens。
  • world loss 同时来自 human 与 robot，权重 $\lambda=1$。
  • Pixel 过度保留外观，强视频先验甚至会 hallucinate 错误物理状态。
  • DINO feature 最擅长新物体和新场景，但仍受 image-grid ego-motion 影响。
  • 3D Flow 用 Aria VIO 消掉头动，最适合空间精确操作。
  • Flow-only 已优于 Action-only；Action+Flow 最好，动作仍提供 task relevance。
  • world head 训练后删除，4090 上 action policy 以 30 Hz 运行。
  • world prediction 不条件于 action，因此不是反事实 simulator。
  • 最可复用结论：选择 target 时先问它是否抽象外观、跨本体一致、消除相机自运动。

一句话记忆：不要强迫人类数据教机器人“手怎么动”，先让它教模型“世界怎样变化”。
