Context Unrolling
in Omni Models

Native Multimodal · Shared Workspace · Text / Image / Video / 3D Context

这篇论文的核心不是“又做了一个多任务模型”,而是把统一多模态模型重新解释成一个可调用上下文构造器:模型先调用文本、视觉 token、相机位姿、深度、novel view synthesis 等原子能力,把中间结果写回共享 context,再做最终预测。

Omni Model Context Unrolling Multimodal CoT 3D Reasoning Generation

0一句话结论

痛点. 现有 omni / unified multimodal model 常被当成“一个 backbone 接多个任务头”,但这种理解没有解释为什么统一模型会在复杂推理和生成中变好。

核心招. 论文提出 Context Unrolling:把文本思考、视觉 token rollout、相机位姿、深度、novel view synthesis 等能力当成可调用 primitive,逐步构造上下文 $C_T$,再用 $C_T$ 条件化最终解码。

效果. Omni 在理解、图像生成/编辑、视频生成/编辑、3D 位姿和深度上都有竞争力;在分析实验中,GenEval2 从 29.25 提到 53.44,空间理解从 27.14 提到 34.17,深度 $\delta_1$ 从 83.21% 提到 84.01%。

代价. 论文更像范式论文和系统展示,训练配方、数据规模、tokenizer、loss、MoE routing 等关键复现细节严重不足;很多结果依赖内部 benchmark、inhouse evaluation 或 oracle context。

§ 1 · POSITIONING

论文定位:统一模型不是任务容器,而是上下文工作台

这篇论文讨论的是 native multimodal / omni model 范式。模型原生训练在文本、图像、视频、3D 几何和 hidden visual representations 上,支持 understanding、generation、editing、camera estimation、depth estimation 等多类输入输出。

它基于 BAGEL 的设计哲学继续扩展,使用 MoE 架构,论文称有 3B active parameters。与 Qwen3-VL、InternVL3.5 这类偏理解的 VLM,或 Flux、Z-Image、Wan、Hunyuan 这类偏生成的专用模型相比,Omni 的目标不是在单项任务上做一个专用最优专家,而是让多个能力在同一个模型里互相调用。

论文的关键差异是:它把统一模型的收益解释为 context construction。直接回答是 $x\\rightarrow y$;Context Unrolling 是先生成若干中间 context,再回答:文本 context 提供语义约束,视觉 token 提供结构脚手架,3D context 提供几何约束,novel views 提供“想象出的证据”。

旧理解

Unified model = 多任务容器

  • 把理解、生成、编辑、3D 放进同一个 backbone
  • 收益主要来自参数共享和数据共享
  • 推理时仍常常是单步 direct decoding
新理解

Unified model = context 工作台

  • 每个能力都是可调用 primitive
  • primitive 输出被写入共享 context
  • 最终预测是 context-conditioned inference
这篇文章最有价值的 insight 是:多模态统一的真正收益,不只是“什么都能做”,而是“做 A 之前可以先调用 B/C/D 来构造更好的上下文”。
§ 2 · PIPELINE

方法总览:从输入到 context 再到输出

论文没有给出完整网络结构图,但给出了清晰的推理抽象。整体 pipeline 可以概括为:

  1. 输入 $x$ 可以是文本、图像、视频、多图、编辑指令、3D 任务请求等。
  2. 模型根据任务选择 primitive:describe、text-think、roll out visual tokens、predict camera pose、synthesize novel views、estimate depth。
  3. 每一步 primitive 产生一个中间 context $\\phi_t(x,C_t)$。
  4. 中间 context 通过组合算子 $\\oplus$ 写入共享 workspace。
  5. 最终 decoder $\\psi$ 在 $x$ 和 $C_T$ 条件下输出文本答案、图像、视频、depth image 或 camera 参数。

§ 3 · INNOVATIONS

关键创新点:把能力变成 primitive

创新 1

Context Unrolling formalism: 从 direct answer 到 iterative context

旧方法为什么不行. 多模态模型即使支持多种输入输出,推理时也常被当成端到端黑盒。遇到复杂生成或空间推理,单步 latent reasoning 容易丢掉数量、位置、视角、遮挡等约束。

怎么改. 论文把推理写成 $C_{t+1}=C_t\\oplus\\phi_t(x,C_t)$,最后 $y=\\psi(x\\mid C_T)$。其中 $\\phi_t$ 是可调用 primitive,$C_t$ 是逐步增长的共享 context。

为什么有效. 多模态世界知识不是单一投影。文本擅长抽象约束,图像 token 擅长结构,几何输出擅长空间关系。把它们显式写入 context,相当于让模型先做可见的中间约束构造。

代价/限制. 这会增加推理 token 和解码步骤;如果中间 context 错了,错误会被后续步骤放大。论文没有给出自动选择 primitive 的策略。

创新 2

Self-unrolled text + visual contexts for generation

旧瓶颈. 文本到图像本身是一对多映射。短 prompt 往往没有写清物体数、属性、关系和位置,导致生成模型靠模糊先验补全。

怎么改. 生成图像前,Omni 先自己生成短/长 textual specification,或者 rollout visual tokens,再把这些 context 输入生成过程。

为什么有效. 文本 context 像 prompt rewriting,把隐含要求显式化;视觉 tokens 像粗 layout,给后续像素生成提供结构锚点。两者互补,所以 long text + visual 的 GenEval2 分数最高。

代价/限制. 自生成 context 会带入 hallucination;oracle context 用 Gemini-3 Pro 得到上界,但这不是单模型闭环的真实部署成本。

创新 3

3D geometry as context: camera pose 和 NVS 不只是输出

旧瓶颈. 纯文本 CoT 处理多视角空间问题很弱。视角变化、遮挡、左右关系会让语言推理丢失真实几何。

怎么改. 论文让模型先估计相机相对位姿,把结果作为 3D textual context;或者先合成 canonical novel views,把“想象出的视角”作为 visual context。

为什么有效. 位姿把“我从哪看”显式化,NVS 把未观察视角补出来。对空间题来说,这比自由文本解释更接近任务所需证据。

代价/限制. Camera 参数被纯文本 tokenizer 编码,没有专门几何 tokenizer;数值精度、尺度归一化和错误传播都没有展开。

创新 4

Depth generation with task-relevant context

旧瓶颈. 把 depth 当成图片生成任务时,模型可能只学到粗颜色-深度先验,细物体、灯、墙面深度差容易错。

怎么改. 估计深度前,模型先生成 depth caption,只描述 front/back ordering、occlusion、support/contact 等几何线索;再叠加 visual token context。

为什么有效. Generic caption 几乎没帮助,depth caption 有帮助,说明 context 不是越多越好,而是越“约束任务”越好。

代价/限制. 提升幅度不大:论文表 4 中 $\delta_1$ 从 83.21% 到 84.01%。这说明 context unrolling 对深度有帮助,但还没有替代强专用几何模型。

创新 5

Hidden reasoning space: 给 latent multimodal reasoning 留接口

旧瓶颈. 如果所有中间推理都必须变成文本,视觉结构和几何关系会被压缩损失。

怎么改. 论文称 Omni 引入 hidden reasoning space,并把 hidden visual representations 作为训练模态之一。

为什么有效. 这给模型提供了非文本的中间表示空间,让视觉/几何信息不必全部语言化。

代价/限制. 【不确定】论文没有说明 hidden space 的 tokenizer、loss、训练比例和与可见 context 的接口。合理猜测是沿用 BAGEL 式离散视觉 token 或内部 latent code;验证方式是等官方代码,或看模型是否暴露 visual-token rollout API。

# 论文抽象出的 context unrolling 伪代码
C = empty_context()
for t in range(T):
    primitive = choose_primitive(x, C)       # e.g. text-think / camera / NVS / visual-token rollout
    c_new = primitive(x, C)                 # phi_t(x, C_t)
    C = compose(C, c_new)                   # C_{t+1} = C_t (+) c_new

y = decode(x, C)                            # psi(x | C_T)
§ 5 · FORMULAS

公式和算法:把关键表达拆开

Formula 1 · Context Unrolling

$$C_{t+1}=C_t\\oplus\\phi_t(x,C_t),\\quad y=\\psi(x\\mid C_T)$$
$x$ 是多模态输入,$C_t$ 是第 $t$ 步已有 context,$\\phi_t$ 是 atomic primitive,$\\oplus$ 是 context composition,$\\psi$ 是最终 decoder。实现上,$C_t$ 可能是文本 token、视觉 token、图像、视频帧、相机数值文本或 hidden states 的混合序列。

Formula 2 · Direct Prediction vs Context-conditioned Prediction

$$\\text{Direct: } y=f(x)$$ $$\\text{Unrolled: } y=\\psi(x\\mid C_{text},C_{vis},C_{geo},C_{hid})$$
论文的核心差异就在这里:不是直接从 prompt 到 image,也不是直接从 RGB 到 depth,而是先把任务相关的上下文显式构造出来。

Formula 3 · Depth as Context-conditioned Generation

$$D=Depth(I\\mid C_{text},C_{vis})$$
$I$ 是输入 RGB,$D$ 是输出深度图。$C_{text}$ 可以是 depth caption,$C_{vis}$ 是 visual tokens。论文表 4 显示 generic detailed caption 几乎无效,depth caption 和 visual tokens 更有效。

Formula 4 · Camera Pose as Text

$$C_{geo}=\\texttt{}\\ t_x\\ t_y\\ t_z\\ r_x\\ r_y\\ r_z\\ \\texttt{}\\ \\texttt{}f_h\\texttt{}\\ \\texttt{}f_w\\texttt{}$$
项目页说明 novel view generation 的 instruct 会包含相机位姿和 FOV,且整个 instruct 由 language tokenizer 编码,没有单独几何 encoder。这是很大胆的设计,也暴露了数值精度和泛化风险。

Formula 5 · Visual Generation with Rolled Context

$$I_{out}\\sim p_\\theta(I\\mid x,C_{short/long},C_{visual})$$
这不是论文原文中的显式训练目标,而是对表 2 实验的实现抽象。$C_{short/long}$ 是模型自生成的文本改写,$C_{visual}$ 是离散视觉 tokens。GenEval2 中 long + visual 达到 53.44,明显高于 baseline 29.25。

支持结论的地方

趋势比较一致

  • 越任务相关的 context 越有帮助
  • 文本 context 和视觉 context 互补
  • 3D context 对空间推理比普通 CoT 更有效
  • 统一模型能覆盖理解、生成、视频和 3D
需要警惕的地方

公平性并不完美

  • 内部 downsampled benchmark 和 inhouse evaluation 比例较高
  • 很多 baseline 是专用模型,训练数据和算力不同
  • oracle context 使用外部 Gemini-3 Pro,不是同一系统能力
  • 缺少 context 成本:多生成 100/250 tokens、visual tokens 或 NVS 的延迟没有报告
  • 训练配方缺失,复现实验很难验证
实验最可信的部分是“context 类型越贴近任务约束,收益越明显”;最不够的部分是“没有完整说明如何训练出能稳定产生这些 context 的 Omni”。
§ 8 · REPRODUCTION

可复现清单:先复现机制,别急着复现整模

基础模型. 需要一个支持 text/image/video/generation/editing/3D 的统一模型。论文称 Omni 是 MoE,3B active parameters,基于 BAGEL 思路。
context primitives. 至少实现 text-think、visual-token rollout、camera pose text、NVS、depth caption 五类 primitive。
prompt 预算. T2I 中 short thinking 平均约 100 tokens,long thinking 约 250 tokens。复现时要固定 token budget。
几何文本格式. NVS 使用 <campose>tx ty tz rx ry rz</campose> 和双 FOV 标签,整个 instruct 走 language tokenizer。
depth 协议. 把 depth 当 image generation,比较 no context、generic caption、depth caption、visual tokens 四组。
空间 QA 协议. 在 MMSI 类多图空间问题上比较 direct、text thinking、camera pose textual context、NVS visual context。
成本记录. 必须记录额外 token、额外 forward、NVS 时间、context 长度,否则 context unrolling 的代价被隐藏。
上下文质量评估. 对 self-rollout context 做人工/模型评分,区分 context 本身错误和 final decoder 错误。

§ 10 · MEMORY CARD

速读备忘卡:下次回忆用

  • Omni 是一个 native multimodal unified model,覆盖文本、图像、视频、3D 几何和 hidden reps。
  • 论文称模型有 3B active parameters,MoE 架构,基于 BAGEL 设计哲学。
  • 核心概念是 Context Unrolling:先构造 context,再最终预测。
  • 核心公式:先用 primitive 更新 context,再基于最终 context 解码。
  • Context 可以是文本 thinking、visual tokens、camera pose、novel views、depth caption。
  • T2I 中 long text + visual context 把 GenEval2 从 29.25 提到 53.44。
  • 空间推理中 visual contexts 把 MMSI subset overall 从 27.14 提到 34.17。
  • Depth caption 比 generic caption 更有效,说明 context 要任务相关。
  • 3D 能力不是单独炫技,而是作为下游推理的 context primitive。
  • 实验亮点强,但复现弱:训练细节、数据、tokenizer、loss、MoE routing 都没充分披露。
  • 最重要的未来方向是让模型自动决定何时、用什么模态 unroll context。
  • 一句话记忆:Omni 的价值不是“多模态输出”,而是“多模态思考过程可被写入上下文”。
