Orca：把世界模型的目标从输出预测改成状态预测

Next-State Prediction · World Latent · Multimodal Readouts

Orca 的核心不是“一个模型同时会聊天、画图、控制机器人”这么简单，而是把世界模型的中心对象从输出端迁到 latent state：先用 observation-only 和 event-conditioned 两类 state transition 训练一个世界 latent，再冻结 backbone，用语言、图像、动作 readout 去验证这个 latent 是否真的携带世界变化的信息。

World Foundation Model Next-State Prediction Qwen3.5 Robot Action Readout

0一句话结论

痛点。 现有基础模型多围绕输出接口训练：LLM 做 next-token，视频模型做 next-frame，VLA 做 next-action；这些目标各自有效，但没有明确逼模型形成可被多种接口复用的“世界状态”。

核心招。 Orca 用 Qwen3.5 VLM 做 encoder，通过 learnable queries 预测冻结视觉编码器空间里的未来/事件目标 visual latent，同时保留 VQA next-token 监督，最后冻结 backbone，只训练轻量 readout 到文本、图像和动作。

效果。 Orca-4B 在文本 readout 平均 51.8，高于 Qwen3.5-4B 的 46.7；在 PRICE-V0.1 图像状态预测平均 59.8，超过 Flux.2 [klein] 的 56.1；在真实机器人 OOD action readout overall rule-based 32.4，高于 pi0.5 的 29.4、V-JEPA 2.1 的 17.0 和 Qwen3.5 的 10.5。

代价。 训练依赖 32 nodes / 256 GPUs、12.5K hours 实际预训练视频、160M event inventory 的数据工程；当前只在 0.8B/4B 规模验证，监督仍绑定冻结 ViT 空间，项目页未公开官方代码。

§ 1 · POSITIONING

这篇到底在解决什么：让 world latent 成为共同中间层

Orca 把问题定义为 latent world-state modeling。它不是只训练一个更强 VLM，也不是只训练一个机器人 policy，而是要学习一个 \(S_t\)：这个状态可以从视觉和语言信号里抽象出来，又能被语言、图像、动作三种 readout 读出去。

和 JEPA 类模型相比，Orca 不满足于 observation-only latent prediction，而是加入语言事件条件和 VQA，让 latent 同时学自然动态、事件语义和常识问答。和 VLA / WAM 相比，Orca 的预训练不依赖 action labels，而是先学状态变化，再用少量 action-labeled trajectories 训练 Action Expert。

范式中心目标学到什么Orca 的差异
Next-token 预测语言 token 语义、知识、推理接口 语言只是显式条件和 readout，不是唯一训练中心
Next-frame / video generation 预测像素或视频 latent 视觉动态和生成能力 Orca 预测冻结 ViT latent，不直接追求像素重建
Next-action / VLA 预测动作 chunk policy 和 affordance 动作只作为 downstream readout，预训练先学世界变化
Next-state / Orca 预测世界 latent state transition 可读出文本、图像、动作的共享状态表征 用 frozen-backbone probing 证明 latent 能迁移到多个输出接口
核心 insight：Orca 不是把所有输出都塞进一个 decoder，而是先训练一个“可被多种 decoder 读取”的世界 latent。
§ 2 · FORMULATION

方法总览：两个 state-transition 目标加一个语言监督

\[ S=f_\theta(X), \qquad S_{t+\Delta}\sim p_\Theta(S_{t+\Delta}\mid S_t,z_t,c_t),\quad \Delta\in\mathbb{Z}\setminus\{0\} \]

这里 \(X=\{X_m\}_{m\in M}\) 是多模态世界信号；当前版本主要用视觉和语言。\(S_t\) 是抽象 world state；\(z_t\) 表示不可见动态因素，例如物理规律、物体属性、环境力；\(c_t\) 是显式条件，例如事件描述、任务意图、因果前提。

visual frame v_t
-> Qwen3.5 VLM encoder + learnable Query 1
-> hidden(q_1) -> 2-layer MLP -> predicted visual latent \hat{v}^l_{t+1}
-> match frozen ViT latent v^l_{t+1}

visual frame v_t + event text e_{t+\Delta}
-> Qwen3.5 VLM encoder + Query 1 + Query 2
-> hidden(q_2) -> MLP -> predicted event-target latent \hat{v}^l_{t+\Delta}
-> match frozen ViT latent v^l_{t+\Delta}

video V + question l_q
-> LM head -> answer l_a
§ 3 · INNOVATIONS

关键创新点：从 slogan 还原到张量

Innovation 1

Unconscious learning：从连续视频里学密集自然动态

旧方法为什么不行。 只靠语言或 VQA 很难学到物体运动、遮挡、惯性、接触等低层连续变化；只做像素重建又容易把训练目标浪费在纹理。

它怎么改。 输入当前帧 \(v_t\) 和 learnable Query 1，取 Query 1 的最后层 hidden state，经两层 MLP 预测下一帧的视觉 latent \(\hat{v}^l_{t+1}\)，目标 \(v^l_{t+1}\) 来自冻结 vision encoder。

为什么有效。 Query 1 成了一个“预测插槽”：它不需要输出文本，而是专门吸收当前视觉状态中对下一状态有用的信息。监督在 ViT latent 空间进行，比像素空间更偏语义和结构。

代价/限制。 这个 latent 是否保留足够几何和动力学细节，取决于冻结 vision encoder。论文自己也承认 ViT-space supervision 会把世界状态绑定到已有语义空间。

Innovation 2

Conscious learning：用事件语言指定“应该转到哪个状态”

旧方法为什么不行。 observation-only 学到的是自然临近转移，但很多智能行为需要理解“做某件事之后世界应如何变化”，这不是单纯下一帧能覆盖的。

它怎么改。 把视频切成粗粒度和细粒度事件，每个事件有语言 caption。输入 \(v_t\)、Query 1、事件描述 \(e_{t+\Delta}\)、Query 2，让 Query 2 预测前一个或后一个事件中的随机目标帧 latent。

为什么有效。 语言事件提供了稀疏但有意义的 state transition supervision：比如“关上微波炉门”不是预测下一帧纹理，而是预测动作完成后的状态。

代价/限制。 事件标注质量决定上限。论文说有 160M event annotations，但没有开放完整标注器、过滤规则和数据配比。

Innovation 3

Frozen-backbone readout probing：证明 latent 有用，而不是 decoder 很强

旧方法为什么不行。 如果 backbone 和 decoder 一起 fine-tune，结果变好很难归因：到底是世界 latent 更强，还是 decoder 记住了任务。

它怎么改。 预训练完成后冻结 Orca backbone。语言 readout 直接复用 LM head；图像 readout 只训练 SD3.5 上的 MLP adaptor 和 LoRA；动作 readout 只训练 DiT Action Expert。

为什么有效。 这相当于 probing：如果不同 readout 都随预训练数据和模型规模变强，就说明共享 latent 的质量在提升。

代价/限制。 读出能力仍受 decoder 选择影响。图像 readout 依赖 SD3.5，动作 readout 依赖 DiT Action Expert；它证明 latent 可读出，但不等价于端到端最优。

§ 4 · TRAINING

训练和推理流程：先训练 encoder，再冻结读出

阶段输入输出训练哪些模块
Pre-training / \(L_{obs}\) 当前帧 \(v_t\)、Query 1 下一帧 ViT latent \(\hat{v}^l_{t+1}\) Qwen3.5 LLM、learnable queries、visual transition MLP；vision encoder frozen
Pre-training / \(L_{evt}\) 当前帧 \(v_t\)、事件文本 \(e_{t+\Delta}\)、Query 1/2 前/后相邻事件目标 latent \(\hat{v}^l_{prev/next}\) 同上，Query 2 负责 event-conditioned predictive state
Pre-training / \(L_{vqa}\) 视频 \(V\)、问题 \(l_q\) 语言答案 \(l_a\) 标准 next-token LM head 监督
Readout post-training 冻结 Orca latent 文本、目标图像、动作 chunk 只训练对应 readout；Orca backbone frozen

预训练主设置：Orca-4B 基于 Qwen3.5-4B，hidden size 2560；Orca-0.8B 基于 Qwen3.5-0.8B，hidden size 1024。两者都用 32 nodes / 256 GPUs，训练 10,844 steps，最大序列长度 1024，warmup 200 steps，AdamW，基础 VLM learning rate \(3.5\times10^{-5}\)，visual head learning rate \(1.2\times10^{-4}\)，learnable queries 数量 256。

论文说 inventory 有 125K hours video、160M event annotations、11.5M VQA；但 v1 当前实验只用了十分之一视频，即约 12.5K hours。这一点很关键：Orca 的 claim 是范式和 scaling trend，而不是已经吃完所有数据。

§ 5 · FORMULAS

公式/算法逐行讲解：loss 对应什么操作

\[ \ell_{lat}(\hat{v}^l,v^l)=0.1\|\hat{v}^l-v^l\|_2^2+ 0.9\left(1-\frac{\langle \hat{v}^l,v^l\rangle}{\|\hat{v}^l\|_2\|v^l\|_2}\right) \]
项含义实现视角风险
\(\hat{v}^l\) Query hidden state 经过 visual transition head 后预测出的视觉 latent Orca-4B 的 visual head 是 \(2560\to20480\to2560\) 两层 MLP 如果 query 学不到状态压缩，就会退化成弱特征预测
\(v^l\) 目标帧通过冻结 vision encoder 得到的 latent teacher forcing 目标，不反传到 ViT 世界状态被固定 ViT 表征约束
0.1 MSE 对齐绝对向量位置 让 predicted latent 不偏离 teacher latent 高维 latent 中 MSE 可能过分惩罚无关方向
0.9 Cosine 对齐方向/语义相似性 更像 representation alignment 只保方向可能丢失尺度信息
\[ L_{obs}=\mathbb{E}[\ell_{lat}(\hat{v}^l_{t+1},v^l_{t+1})] \] \[ L_{evt}=\frac{1}{2}\mathbb{E}\left[ \ell_{lat}(\hat{v}^l_{prev},v^l_{prev})+ \ell_{lat}(\hat{v}^l_{next},v^l_{next}) \right] \] \[ L_{pre}=0.1L_{obs}+0.5L_{evt}+0.4L_{vqa} \]

\(L_{obs}\) 是无条件的临近未来预测，管自然连续动态；\(L_{evt}\) 是语言指定目标事件的双向预测，管“这个事件发生前/后世界应该是什么样”；\(L_{vqa}\) 是标准语言建模，保留语言接口和常识 grounding。采样层面，论文写 state transition samples 和 VQA samples 约按 5:1 混合。

§ 6 · DATA

数据系统：world latent 不是只靠机器人数据训出来的

数据类型包含什么服务哪个目标价值
A. Video Data ego-centric interaction、exo-centric manipulation、action-free robot execution、natural dynamics \(L_{obs}\) 和 \(L_{evt}\) 提供连续视觉状态变化和真实物理互动
B. Event Data 粗/细粒度事件分割和 caption \(L_{evt}\) 把“下一状态”从邻近帧扩展到有语义意义的事件结果
C. VQA Data 基于语言和视频构造的问答 \(L_{vqa}\) 保留语言 readout 能力和常识/因果解释
Data Insight

为什么 action readout 能受益于无 action 预训练

论文的关键证据是：pre-training 没有 action labels，但 action readout 随预训练 scale 变强。合理解释是，视频中的物体运动、局部接触、状态转移先验降低了 Action Expert 的学习难度。它不是让 Orca 直接会控制，而是给下游 action decoder 一个更接近“未来状态”的条件。

§ 7 · TRAIN / INFER GAP

训练-推理对齐：读出是 probing，也是约束

Aligned

对齐的地方

预训练和 readout 都围绕 latent state 展开：预训练要求 Query 预测未来/事件目标视觉 latent；readout 则从这个 latent 读出文本、图像、动作。论文用冻结 Orca backbone 减少了“readout 反过来改 backbone”的归因混乱。

Action readout 的条件也很明确：Orca latent \(q_1\)、noisy action + time embedding、proprioception。它输出 action horizon 30、action dimension 16 的动作 chunk，推理 timesteps 为 4。

Mismatch

不一致的地方

预训练目标是 frozen ViT latent，不是像素、三维状态或真实动力学变量。图像 readout 依赖 SD3.5 的生成能力，动作 readout 依赖额外真实机器人数据。读出结果好，不代表世界 latent 已经是完整物理状态。

V1 论文没有公开官方训练代码和数据构造脚本，query 插入位置、token layout、目标帧采样、event segmentation 细节仍然需要等代码或数据文档确认。

§ 8 · EXPERIMENTS

实验复盘：最强证据是 frozen readout scaling

评测关键结果批判性解读
Text generation Orca-4B avg 51.8；Qwen3.5-4B avg 46.7；Orca-0.8B avg 40.8 提升主要来自 TemporalBench、3DSRBench、SWITCH；但 V-JEPA 2.1 部分结果来自原论文，且不是所有 benchmark 都可比。
PRICE-V0.1 image prediction Orca 4+2 avg 59.8±10.9；Flux.2 [klein] 56.1±18.1；FLUX.1-Kontext 40.9±13.5 PRICE 聚焦真实互动后的目标状态，符合论文问题；但 judge 包括多个闭源模型，分数受 prompt 和 judge 偏好影响。
Real-robot action readout Overall rule-based：Orca 32.4，pi0.5 29.4，V-JEPA 2.1 17.0，Qwen3.5 10.5 这是最贴近具身价值的证据；但成功率本身很低，任务只有 5 个，且比较的是冻结 latent + 各自 action expert / official pi0.5 post-training。
Ablation 三项 loss 全开：Text 51.8、Image 59.8、Action 32.4、Average 48.0 支持“三目标互补”的主张。尤其 \(L_{obs}\) 对 action readout 重要，\(L_{evt}\) 对 image prediction 重要，\(L_{vqa}\) 保语言接口。

我认为这篇最可信的证据不是某个单点 SOTA，而是两个趋势：第一，pre-training loss 随数据和模型规模下降；第二，冻结 backbone 后，文本、图像、动作 readout 都随预训练 scale 提升。这比“某个 decoder 调得好”更能说明 latent 在变强。

Uncertainty

【不确定】world latent 具体是哪一个张量

论文语义上说 world latent，但实现里至少有三类候选：1. VLM 最后层 hidden states；2. Query 1/Query 2 的 predictive hidden states；3. MLP 后预测的 visual latent。图像和动作 readout 里更像使用 Query latent 或其 MLP adaptor 输出。验证方式：等官方代码，看 readout 模块 forward 的 condition tensor 来源、shape 和 layer index。

§ 10 · FASTWAM

对 FastWAM / 具身操作的启发

Orca 对 FastWAM 最有启发的地方是 predictive query state。FastWAM 里如果只用当前视觉 token 或最终 hidden state 做 action condition，可能缺少“下一状态应该是什么”的结构化中间变量。Orca 的 Query 1/2 设计提供了一个简单模板：用专门 query token 承载未来状态预测，再把这个 token 作为 action decoder 的条件。

第二个启发是预训练不一定要等 action labels。Orca 的 action readout 结果说明，大规模视频 state transition 预训练可以降低少量机器人轨迹下 action expert 的学习难度。对 FastWAM 来说，可以先用互联网/ego/robot video 做 latent transition，再用少量动作数据接 action head。

但别把它理解成“无动作数据也能直接控制机器人”。Orca 仍然用 200 trajectories/task 训练 Action Expert；真实控制能力来自 world latent 和 action-labeled post-training 的组合。

§ 11 · IMPROVEMENTS

可能改进方向

改动点预期收益风险验证实验
把 proprioception / tactile / force 加入 pre-training state 让 world latent 不只依赖视觉和语言，更接近真实物理状态 多传感器同步、尺度归一化和缺失模态处理复杂 接触类任务上比较 vision-only vs force-aware latent 的 action readout
从 ViT-space teacher 转向 native world latent 减少冻结视觉 encoder 对状态空间的限制 训练不稳定，缺少可靠 teacher 同等数据下比较 ViT latent、VAE latent、object-centric latent 的 readout scaling
长 horizon event chain 预测 让模型学习分钟级之外的计划和状态演化 event annotation 噪声和 compounding error 更重 多事件预测 benchmark：给起点和目标，要求预测中间状态序列
把 Action Expert 和 world latent 做闭环 rollout training 减少 action readout 只看单步 latent 的 mismatch 真实机器人数据成本高，仿真到真实偏差明显 RoboTwin / real robot 上比较 open-loop chunk vs latent rollout policy

§ 12 · MEMORY CARD

速读备忘卡

  • Orca 的中心主张是 next-state prediction，不是单纯多任务输出。
  • 它先训练 world latent，再冻结 backbone，用不同 readout 检验 latent。
  • Unconscious learning：当前帧 + Query 1 预测下一帧 frozen ViT latent。
  • Conscious learning：当前帧 + 事件文本 + Query 2 预测前/后事件目标 latent。
  • VQA response generation 保留语言接口和常识 grounding。
  • latent matching loss 是 0.1 MSE + 0.9 cosine。
  • 总预训练损失是 \(0.1L_{obs}+0.5L_{evt}+0.4L_{vqa}\)，transition:VQA 采样约 5:1。
  • Orca-4B 基于 Qwen3.5-4B，训练用 32 nodes / 256 GPUs，当前只用 12.5K hours 视频。
  • 图像 readout 用 frozen SD3.5 + MLP adaptor + LoRA；动作 readout 用 DiT Action Expert。
  • 真实机器人结果证明 world latent 对 action decoder 有帮助，但成功率仍低，任务范围有限。
  • 最大弱点是 ViT-space supervision、代码/数据未公开、world latent 张量定义需要代码确认。
