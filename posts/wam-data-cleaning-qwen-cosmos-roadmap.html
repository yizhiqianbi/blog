WAM 数据清洗路线：先对齐，再扩规模

这篇不是模型论文解读，而是一份开工路线： 面对 LeRobot、HDF5、RLDS、纯视频、仿真和多机器人数据，如何先把数据变成可追踪、可回滚、可按任务采样的 WAM 训练资产。

2026.06.23 阅读约 22 分钟 Data Cleaning Roadmap

0. 一句话结论

WAM 数据清洗的第一原则不是“尽快把所有数据洗成同一种 action”，而是 alignment first, then scale：先建立 raw manifest、数据分桶、schema version、mask、频率和相机约定， 再做语义 recaption、平衡采样和大规模 LeRobot/WebDataset 输出。

核心痛点
机器人数据不是普通视频数据。action 维度、坐标系、控制频率、相机视角、gripper 语义和任务文本粒度都可能冲突。
核心招
保留 raw 数据，新增 canonical 数据；所有 absent slot 必须有 mask；所有转换必须可回滚。
工程判断
VLM semantic filtering 应该放到第二阶段。第一阶段先做 inventory、hard filters 和 schema alignment。

1. 最近几篇报告给我们的共同信号

来源 对数据清洗的启发 落到 pipeline 里是什么
Qwen-RobotManip 没有 action semantics 对齐，更多数据会破坏模型。 canonical vector、binary mask、camera-frame delta EEF、calibration quality flag。
Qwen-VLA 统一的是 action/trajectory tensor 接口，不是强行统一物理语义。 embodiment prompt、control Hz、chunk size、per-dataset quantile normalization。
Qwen-RobotWorld 无低层 action 的视频也有价值，但应该走 action-rich caption。 video-only branch、high-level task、low-level subtask、success condition、object/state change caption。
Cosmos 3 action token 是 \(v_{t-1}\rightarrow v_t\) 的状态转移。 frame/action timestamp 必须对齐；control rate 和 physical time 必须进 metadata。

2. 数据先分桶，不要一锅炖

PDF 里的数据统计已经覆盖 action-labeled robot、ego video、sim/eval benchmark 等多类数据。 第一阶段应该先分桶，而不是直接合成一个巨大的训练池。

桶 代表数据 第一阶段用途
Action-labeled robot DROID、AgiBotWorld、RoboMIND、InternData-A1、RDT-1B、Mobile ALOHA、RH20T policy / WAM action modeling；优先做 state-action-video 对齐。
Video-only ego / ego-exo EgoDex、Ego4D、EgoCentric、Ego-Exo4D RobotWorld 式 action-rich caption；不要伪造低层 action。
Simulation / eval LIBERO、CALVIN、RoboTwin、RoboCasa schema debug、benchmark adapter、closed-loop eval；不要一开始就混入主池。
Low-confidence / unknown convention 缺标定、缺 action convention、帧率/时间戳不可靠的数据 先 quarantine，只出 manifest 和质量报告。

3. 最小数据契约：先写 manifest

不要从“读出来一个 tensor”开始。先从 manifest 开始，因为后面每一步 filter、transform、recaption、sampling 都需要可追踪。 

episode record:
  dataset_id
  episode_id
  source_path
  robot_type
  embodiment_tags
  camera_names
  fps
  control_hz
  frame_count
  duration
  has_action
  has_state
  has_calibration
  instruction_raw
  filter_status
  filter_reasons
  schema_version

frame record:
  episode_id
  frame_index
  timestamp
  video_frame_idx
  state_raw
  action_raw
  state_mask
  action_mask
  camera_frame_refs

每个 stage 输出一个新 manifest，而不是覆盖旧文件： 

raw_manifest.jsonl
  -> stage1_hard_filter_manifest.jsonl
  -> aligned_manifest.jsonl
  -> semantic_manifest.jsonl
  -> sampling_manifest.jsonl

4. Hard filters 先跑，语义模型后跑

第一阶段只做便宜、确定、可解释的硬过滤。VLM/CLIP progress check 计算贵、误判多，应放在第二阶段作为弱标签或权重，而不是 hard delete。

处理 规则 建议
硬删 视频打不开；首帧/尾帧 decode 失败；metadata 损坏；frame/action 长度对不上。 这些样本无法可靠训练。
硬删或隔离 action/state NaN/Inf，且该数据声明有 action。 无 action 数据不适用这个规则，应该进 video-only branch。
标记 静止、抖动、模糊、低亮度、过曝、超长/超短。 先写 quality tags，不要全删；失败恢复和等待片段可能有用。
后置 CLIP 首尾帧进展、VLM recaption、success/failure 判定。 用于 sampling weight 和 semantic split，不作为第一阶段入口。

5. Action schema：65D 可以做 v0，但不能当唯一真相

PDF 里提出的 65D 结构有用：主臂 7D、主末端 24D、副臂 7D、副末端 24D、底盘 3D。 但从 Qwen-RobotManip / Cosmos 3 看，清洗层更应该保留两套表示： 

raw_state / raw_action:
  dataset original convention
  units, coordinate frame, controller mode preserved

canonical_state / canonical_action:
  slot-based vector
  binary mask
  schema_version
  action_repr: joint / eef / camera_frame_delta_eef / waypoint / base
  rotation_repr: quaternion raw, 6d model-side optional

关键是：padding 维度必须有 mask。不能只把缺失值填 0，因为 0 可能是一个真实动作。 另外，四元数适合存储和接口，但模型侧可以额外提供 6D rotation，避免旋转表示不连续的问题。

6. Alignment transform 的顺序

  1. camera_unify：统一 `front / wrist_primary / wrist_secondary / overhead` 等名字，保留原始相机名。
  2. frequency_resample：写入 `fps, control_hz, action_dt, action_chunk_size`；先不要盲目全部重采样到 10Hz。
  3. action_space_align：raw action 到 canonical slot；如果缺标定，只标记 `cannot_camera_frame_eef`。
  4. normalizer_stats：按 dataset 和 action dim 计算 mean/std/1%/99% quantile。
  5. instruction_normalize：保留 raw instruction，新增 high-level / low-level / objects / success condition。

Qwen-VLA 的 per-dataset quantile normalization 很适合这里：先把不同平台尺度压到稳定范围， 但不要假装相同数值代表相同物理含义。物理语义仍然靠 schema、mask、prompt 和数据分桶说明。

7. Video-only 数据不要浪费，但不能伪装成 robot action

EgoDex、Ego4D、EgoCentric 这类数据可以给 WAM 很多世界动态和人类操作先验。 但如果没有低层 robot action，就不要强行变成 action regression 数据。

更合理的是 Qwen-RobotWorld 路线：给它生成 action-rich caption。 

video-only episode
  -> high_level_task
  -> subtask_sequence
  -> manipulated_objects
  -> state_changes
  -> success_condition
  -> optional hand/object tracks
  -> world model / language-conditioned future generation branch

后续如果要做人到机器人迁移，再单独做 H2R、retargeting 或 synthetic robot rendering。不要在清洗阶段把这些假设混进主 manifest。

8. MVP：先跑四个 pilot，不要全量开炸

Pilot 为什么选 验收标准
DROID 真实 Franka，LeRobot/parquet，适合验证 state-action-video 对齐。 100 条随机样本能画出首中尾帧、action 曲线、instruction、timestamp 对齐。
RoboMIND 或 AgiBot 多 embodiment，适合验证 slot/mask/schema。 schema coverage 表能看出每个 robot 的有效 slot。
EgoDex 或 Ego4D video-only，适合验证 action-rich caption branch。 不产生 fake action，只产生 semantic/action-rich manifest。
LIBERO 或 RoboTwin 仿真/eval，适合验证 adapter 和 benchmark split。 可以从 manifest 复原 episode，并跑固定采样窗口。

9. 最终流水线

download / unpack
  -> raw inventory manifest
  -> hard metadata/video filters
  -> dataset-specific adapter
  -> raw-to-canonical action/state transform
  -> frequency / camera / instruction normalization
  -> normalizer stats: per dataset, per action dim
  -> semantic recaption / progress scoring
  -> balanced sampling manifest
  -> LeRobot v3 chunks or WebDataset tar shards

训练时再按任务读取：policy 读 action-labeled pool；world model 读 video/action 或 video-only pool； inverse dynamics 读 before/after + action；language-conditioned future generation 读 action-rich captions。

10. 第一周真正要交付什么

  • dataset_card.yaml：每个数据集的 robot、camera、fps、action convention、license/status。
  • raw_manifest.jsonl：全量 episode 索引和路径。
  • filter_report.json：每个 stage 的保留率和 filter reason 分布。
  • schema_coverage.csv：每个 canonical slot 的覆盖率。
  • normalizer_stats.parquet：每 dataset/action dim 的 mean/std/1%/99%。
  • qa_contact_sheet/：每数据集随机 100 条，首中尾帧 + instruction + action 曲线。

只要这六个产物站住，后面才值得谈大规模 recaption、embedding、WebDataset 打包和训练混合比例。
