WAM 数据清洗路线：先对齐，再扩规模

这篇不是模型论文解读，而是一份开工路线： 面对 LeRobot、HDF5、RLDS、纯视频、仿真和多机器人数据，如何先把数据变成可追踪、可回滚、可按任务采样的 WAM 训练资产。

2026.06.23 阅读约 35 分钟 Data Cleaning Roadmap

0. 一句话结论

WAM 数据清洗的第一原则不是“尽快把所有数据洗成同一种 action”，而是 alignment first, then scale：先建立 raw manifest、数据分桶、schema version、mask、频率和相机约定， 再做语义 recaption、平衡采样和大规模 LeRobot/WebDataset 输出。

核心痛点
机器人数据不是普通视频数据。action 维度、坐标系、控制频率、相机视角、gripper 语义和任务文本粒度都可能冲突。
核心招
保留 raw 数据，新增 canonical 数据；所有 absent slot 必须有 mask；所有转换必须可回滚。
工程判断
VLM semantic filtering 应该放到第二阶段。第一阶段先做 inventory、hard filters 和 schema alignment。

1. 最近几篇报告给我们的共同信号

来源 对数据清洗的启发 落到 pipeline 里是什么
Qwen-RobotManip 没有 action semantics 对齐，更多数据会破坏模型。 canonical vector、binary mask、camera-frame delta EEF、calibration quality flag。
Qwen-VLA 统一的是 action/trajectory tensor 接口，不是强行统一物理语义。 embodiment prompt、control Hz、chunk size、per-dataset quantile normalization。
Qwen-RobotWorld 无低层 action 的视频也有价值，但应该走 action-rich caption。 video-only branch、high-level task、low-level subtask、success condition、object/state change caption。
Cosmos 3 action token 是 \(v_{t-1}\rightarrow v_t\) 的状态转移。 frame/action timestamp 必须对齐；control rate 和 physical time 必须进 metadata。

2. PDF 的核心信息：它不是清单，是约束条件

这份 Data Statistics PDF 里最重要的不是“我们有多少 TB 数据”，而是它暴露了四个真实工程约束： 数据格式碎片化、action 语义碎片化、视频规模巨大、标注/embedding 成本会迅速膨胀。 所以清洗系统要先服务三个目标：可追踪、可分层、可回滚。

PDF 信息 直接含义 清洗系统决策
LeRobot v2.0/v2.1 仍然是 episode mp4 + parquet + info.json；v3.0 倾向 chunk/file 大文件和关系型 metadata。 不能把每条 episode 当独立小文件随机扫，IO 会崩。 先生成 inventory manifest，再按 dataset/shard/chunk 组织；训练侧读 LeRobot v3 chunk 或 WebDataset tar。
PDF 提出 65D embodiment vector，并用 mask 或 NaN 处理 padding。 统一 action slot 是必要的，但 65D 不等于物理语义已经对齐。 保留 raw action/state；新增 canonical 65D；用 mask、schema_version、frame convention 标明语义。
10M episodes、500 frames/episode 级别下，frame-level state/action metadata 约 TB 级。 embedding、caption、质量模型不能一上来全量跑。 先抽样 QA 和硬过滤；semantic filter 只在 pilot 或高价值 shard 上跑。
PDF 已经列出 adapters、filters、transforms、writers 的目录草图。 这是一个 DataFiltering 工程，而不是一次性脚本。 用 registry + stage manifest，任何过滤都必须留下 reason 和版本号。

3. 数据先分桶，不要一锅炖

PDF 的数据源可以分成五类。第一阶段应该先分桶和打标签，不要直接合成一个巨大的训练池。 因为 WAM 训练有不同任务：有的需要低层 action，有的只需要视频世界动态，有的只适合 eval。

桶 PDF 中的代表数据 规模信号 第一阶段用途
Action-labeled real robot AgiBotWorld-Beta、RoboMIND、InternData-A1、DROID、Mobile ALOHA、RH20T、RDT-1B、FastUMI、RoboCOIN AgiBot 48.1TB、RoboMIND 12.3TB、InternData-A1 6.72TB、DROID 412GB。 policy / WAM action modeling；优先做 state-action-video 对齐和 schema coverage。
Simulation with action GenieSim3.0、InternData-M1、RoboCasa、RoboTwin、CALVIN、LIBERO GenieSim3.0 39.27TB、InternData-M1 5.1TB、RoboTwin2.0 1.36TB。 adapter debug、closed-loop eval、failure mode 复现；训练混入比例要单独控制。
Video-only ego / ego-exo EgoDex、Ego4D、EgoCentric-10K/100K、Ego-Exo4D、EPIC-Kitchens、HOT3D、EgoLive EgoDex 1.7TB、Ego4D 7.88TB、EgoCentric-10K 18.02TB、EgoCentric-100K 25.04TB。 RobotWorld 式 action-rich caption、human-object dynamics、world model pretraining；不要伪造 robot action。
Benchmark / reproduction set LIBERO-fastwam、RoboTwin2.0-FastWAM、CALVIN HF mirrors LIBERO-fastwam 4.69GB、RoboTwin FastWAM 79.1GB。 固定验证集和论文复现实验；不参与训练池随机混合。
Low-confidence / unknown convention 质量被 PDF 标注为需要严格筛选的 OXE、缺标定或缺控制约定的数据 OXE LeRobot subset 450GB，Open-X subset 1.13TB。 先 quarantine，只出 manifest、质量报告和小样本 QA；通过后再进主池。

4. 最小数据契约：先写 manifest

不要从“读出来一个 tensor”开始。先从 manifest 开始，因为后面每一步 filter、transform、recaption、sampling 都需要可追踪。 PDF 里也明确建议每条样本至少记录 episode video path 和 filter reason，并且每个过滤步骤都更新 JSONL。 

episode record:
  dataset_id
  dataset_version
  episode_id
  source_path
  storage_state: compressed | extracted | migrated | corrupted
  robot_type
  embodiment_tags
  source_type: real_robot | sim | ego_video | eval
  supervision_type: action | state_only | video_only | caption_only
  camera_names
  fps
  control_hz
  frame_count
  duration
  has_action
  has_state
  has_calibration
  instruction_raw
  instruction_high_level
  instruction_low_level
  filter_status: keep | drop | quarantine | downweight
  filter_reasons
  schema_version
  license_or_access_note

frame record:
  episode_id
  frame_index
  timestamp
  video_frame_idx
  state_raw_ref
  action_raw_ref
  state_canonical_ref
  action_canonical_ref
  state_mask
  action_mask
  camera_frame_refs

每个 stage 输出一个新 manifest，而不是覆盖旧文件： 

raw_inventory.jsonl
  -> stage1_integrity_manifest.jsonl
  -> stage2_hard_filter_manifest.jsonl
  -> stage3_aligned_manifest.jsonl
  -> stage4_semantic_manifest.jsonl
  -> stage5_sampling_manifest.jsonl

这样做的实际好处是：任何一次训练崩了，都能反查是哪类 robot、哪个 adapter、哪个 transform、哪个 filter reason 引入了分布偏差。

5. 存储策略：LeRobot v3 负责索引，WebDataset 负责吞吐

PDF 里的存储草图是合理的：dataset 级 info、episode 级 parquet、frame 级 parquet、视频 shard 分开。 但是要避免两个坑：一是每帧都挂巨大 JSON，二是过早把所有文本 embedding 存成 float32。 如果按 PDF 的估算走到 10M episodes、5B frames，65D state/action/mask 本身就会到数 TB 级， 所以列式存储和按需读取不是优化项，而是基本条件。 

dataset/
  info.json
  episodes/episodes-00000.parquet
  frames/frames-00000.parquet
  videos/shard_00000/episode_*.mp4
  embeddings/text_t5xxl_fp16-00000.arrow
  manifests/stage*.jsonl
  reports/filter_report.json
  reports/schema_coverage.csv
字段 建议 原因
文本 embedding 不要默认 float32 全量常驻；优先 fp16/bf16，或按 shard 懒缓存。 PDF 估算 10M episodes 仅 T5-XXL pooled float32 就约 160GB；多模型 embedding 会翻倍。
state/action 用 fixed-size list / Arrow tensor + zstd；raw 和 canonical 分列。 5B frames 级别下，列裁剪和压缩比一次性 JSON 更关键。
视频 保留源编码；只在训练导出阶段生成统一 resolution/fps 的缓存。 几十 TB 数据全量重编码成本高，也会丢失原始证据。
训练 shard 离线导出 WebDataset tar 或 LeRobot v3 chunk。 清洗侧要可审计，训练侧要吞吐，两者不要用同一个物理布局硬扛。

6. DataFiltering 工程骨架

PDF 里已经有一个很好的工程拆法：adapters 负责把不同原始格式读进来，filters 只负责判定质量， transforms 只负责对齐表示，writers 只负责导出训练格式。不要把这些揉成一个巨大的转换脚本。 

DataFiltering/
  configs/
    base.yaml
    pipeline.yaml
    output.yaml
    datasets/
      droid.yaml
      agibotworld.yaml
      robomind.yaml
      ego4d.yaml
      libero.yaml
  src/
    config.py
    registry.py
    pipeline.py
    manifest.py
    adapters/
      lerobot_v21_adapter.py
      hdf5_adapter.py
      rlds_adapter.py
      raw_video_adapter.py
    filters/
      metadata/
        static_motion.py
        jerk_outlier.py
        trajectory_length.py
        nan_inf_check.py
      visual/
        video_integrity.py
        resolution_fps.py
        brightness.py
        blur_detection.py
        motion_magnitude.py
      semantic/
        clip_progress.py
        vqa_quality.py
      diversity/
        sampling_balancer.py
        text_clustering.py
        kinematic_diversity.py
    transforms/
      action_space_align.py
      frequency_resample.py
      camera_unify.py
      instruction_normalize.py
      resolution_transform.py

    writers/

这里最重要的约束是：adapter 不做过滤，filter 不做坐标变换，transform 不偷偷删除样本。 每个 stage 只读入上一个 manifest，输出一个新 manifest 和 report。这样 pipeline 才能重跑、对账和抽样复查。

7. Action schema：65D 可以做 v0，但不能当唯一真相

PDF 提出的 65D embodiment vector 很适合作为第一版 canonical slot，因为它能覆盖单臂、双臂、夹爪、灵巧手和移动底盘。 但它只能说明“维度位置”，不能自动说明“坐标系、单位、控制模式、绝对/相对动作”。

slot 维度 含义 清洗注意点
primary arm 7D X, Y, Z, Quat_X, Quat_Y, Quat_Z, Quat_W 必须记录 base frame / camera frame / end-effector frame；四元数需要归一化和符号约定。
primary effector 24D 灵巧手或夹爪；单自由度夹爪只用第 1 维。 其余维度 mask=0；不要只填 0 后丢掉 mask。
secondary arm 7D 左臂/副臂 pose。 单臂数据 padding；双臂数据要记录左右臂命名是否和数据源一致。
secondary effector 24D 副臂末端执行器。 同样需要 mask；灵巧手维度语义最好另有 hand_schema。
mobile base 3D X, Y, Yaw 区分世界坐标、机器人局部坐标、速度命令和位置命令。 
raw_state / raw_action:
  dataset original convention
  units, coordinate frame, controller mode preserved

canonical_state / canonical_action:
  65d slot vector
  binary mask
  schema_version
  action_repr: joint | eef_pose | delta_eef | waypoint | base_velocity
  frame_repr: world | robot_base | camera | end_effector
  rotation_repr: quaternion_raw, rotation6d_model_optional

对模型而言，四元数不一定是最舒服的旋转表示；训练侧可以额外派生 6D rotation。 但清洗层应该保存原始四元数或源数据 pose，因为这是最接近设备接口的证据。

8. Hard filters：先删坏数据，再谈语义质量

第一阶段只做便宜、确定、可解释的硬过滤。VLM/CLIP progress check 计算贵、误判多，应放在第二阶段作为弱标签或权重，而不是 hard delete。 PDF 里列出的 filters 可以分成 metadata、visual、semantic、diversity 四层。

层级 规则 建议动作
Integrity 视频打不开；首帧/尾帧 decode 失败；metadata/HDF5/json/parquet 截断；frame/action 长度对不上。 硬删或 quarantine；这类样本无法可靠训练。
NaN/Inf action/state 出现 NaN/Inf，且该数据声明有 action/state。 隔离并记录字段；video-only 数据不适用这个规则。
Trajectory length 过短，例如 <10 或 <20 frames；过长，例如 >2000 frames。 先标记，不同任务阈值不同；超长可能需要切段而不是删除。
Static motion state/action 方差接近 0，或首尾视觉几乎不变。 不要全删；等待、reset、失败恢复都可能有价值。建议 downweight 或切掉静止前后缀。
Jerk/outlier action 一阶/二阶差分异常尖峰，或 state derivative 与 action 明显不一致。 孤立尖峰可插值/平滑；连续尖峰 quarantine；阈值按 dataset 分位数设。
Visual quality 分辨率过低、fps 过低、黑屏/过曝、Laplacian blur 过低、遮挡严重。 写 quality tags；只对完全不可见或不可 decode 硬删。
Semantic progress CLIP/VLM 比较首帧/尾帧与 task text 的匹配提升，或 VQA 判断是否完成。 只做 weak label：success_score、progress_score、caption_confidence；不要作为第一轮硬门槛。

一个关键工程细节：filter 输出不应该只有 keep/drop，还要有 reason、metric value、threshold、filter_version。 否则后面发现某个阈值错了，无法恢复被误删的数据。

9. Alignment transforms：顺序比模型更重要

transforms 的目标不是“把所有数据变得一样”，而是把差异显式化。PDF 里列出的 action_space_align、frequency_resample、camera_unify、 instruction_normalize、resolution_transform、action_normalize 都应该是可单独重跑的 stage。

  1. camera_unify：统一 front / wrist_primary / wrist_secondary / overhead / ego 等名字，保留原始相机名、内参、外参和是否可用。
  2. timebase_unify：先记录原始 fps、control_hz、timestamp drift，再决定是否重采样；不要一上来全转 10Hz。
  3. action_space_align：raw joint / EEF / base command 到 canonical slot；如果缺 URDF、标定或 FK，不要伪装成 EEF，只标记 alignment_level。
  4. instruction_normalize：保留 raw instruction，新增 high-level task、low-level subtask、object set、success condition。
  5. normalizer_stats：按 dataset、robot、slot 计算 mean/std/1%/99% quantile；训练时选择 per-dataset 或 grouped normalization。
  6. export_writer：输出 LeRobot v3 和 WebDataset 两套视图；清洗原表不因训练格式而丢字段。
alignment_level:
  0 raw_only
  1 time_aligned
  2 camera_named
  3 joint_to_eef_base_frame
  4 eef_camera_frame_available
  5 calibrated_multi_view_available

Qwen-VLA 的 per-dataset quantile normalization 很适合这里：先把不同平台尺度压到稳定范围。 但不要假装相同数值代表相同物理含义。物理语义仍然靠 schema、mask、prompt 和数据分桶说明。

10. Video-only 数据不要浪费，但不能伪装成 robot action

EgoDex、Ego4D、EgoCentric 这类数据可以给 WAM 很多世界动态和人类操作先验。 但如果没有低层 robot action，就不要强行变成 action regression 数据。

更合理的是 Qwen-RobotWorld 路线：给它生成 action-rich caption，把“人做了什么、对象发生了什么变化、成功条件是什么”写清楚。 

video-only episode
  -> high_level_task
  -> subtask_sequence
  -> manipulated_objects
  -> contact / grasp / release events
  -> visible state changes
  -> success_condition
  -> optional hand/object tracks
  -> world model / language-conditioned future generation branch

后续如果要做人到机器人迁移，再单独做 H2R、retargeting 或 synthetic robot rendering。 不要在清洗阶段把这些假设混进主 manifest，因为 fake action 会污染 action head。

11. Model-in-the-loop 清洗：只能加标签，不能替代数据契约

PDF 里提到 CLIP progress、VQA quality、recaptioning。这些都应该做，但位置要后置。 原因很简单：模型判断的错误通常是系统性错误，直接硬删会把某些机器人、视角、物体、语言风格整体删掉。

模型步骤 产物 使用方式
CLIP start/end progress progress_delta, text_visual_alignment 训练采样权重；人工 QA 排序；不直接删除。
VLM recaption high_level_task, low_level_subtasks, objects, success_condition 补足 instruction 粗细粒度；为 video-only 数据建语言监督。
No-reference video quality quality_score, blur_score, occlusion_score 采样和可视化排序；和硬指标冲突时交给人工抽检。
Text clustering task_cluster_id, long_tail_score 控制大任务过采样，保护小任务和困难任务。

12. 删、降权、隔离：三种决策要分开

数据清洗最容易犯的错是把所有问题都变成 drop。更稳的策略是三类决策分开：

决策 适用样本 原因
Drop 无法 decode、metadata 截断、帧数/action 数无法对齐且无法修复。 训练读不出来或监督错位，保留没有意义。
Downweight 静止片段、轻微模糊、弱 progress、重复任务、大规模低质量来源。 信息量低但不一定有害；可用于 world dynamics 或失败建模。
Quarantine action convention 不清楚、坐标系缺失、FK 不可用、VLM 与 metadata 冲突。 这类数据可能有价值，但不能进入主 action pool。

13. MVP：先跑四个 pilot，不要全量开炸

Pilot 为什么选 验收标准
DROID 真实 Franka，LeRobot/parquet，适合验证 state-action-video 对齐。 100 条随机样本能画出首中尾帧、action 曲线、instruction、timestamp 对齐。
RoboMIND 或 AgiBot 多 embodiment，适合验证 slot/mask/schema。 schema coverage 表能看出每个 robot 的有效 slot；单臂/双臂/人形机器人不互相污染。
EgoDex 或 Ego4D video-only，适合验证 action-rich caption branch。 不产生 fake action，只产生 semantic/action-rich manifest。
LIBERO 或 RoboTwin 仿真/eval，适合验证 adapter 和 benchmark split。 可以从 manifest 复原 episode，并跑固定采样窗口。

14. 最终流水线

download / unpack / migrate
  -> raw inventory manifest
  -> integrity scan: video + metadata + frame count
  -> hard metadata/video filters
  -> dataset-specific adapter
  -> raw-to-canonical action/state transform
  -> frequency / camera / instruction normalization
  -> normalizer stats: per dataset, per robot, per action slot
  -> semantic recaption / progress scoring
  -> diversity balancing: text cluster + kinematic cluster
  -> sampling manifest
  -> LeRobot v3 chunks or WebDataset tar shards

训练时再按任务读取：policy 读 action-labeled pool；world model 读 video/action 或 video-only pool； inverse dynamics 读 before/after + action；language-conditioned future generation 读 action-rich captions。

15. 第一周真正要交付什么

  • dataset_card.yaml：每个数据集的 robot、camera、fps、action convention、license/status、下载/解压/迁移状态。
  • raw_inventory.jsonl：全量 episode 索引、路径、source_type、supervision_type。
  • filter_report.json：每个 stage 的保留率、drop/downweight/quarantine reason 分布。
  • schema_coverage.csv：每个 canonical slot 的覆盖率、mask 比例、alignment_level 分布。
  • normalizer_stats.parquet：每 dataset/robot/action slot 的 mean/std/1%/99%。
  • qa_contact_sheet/：每数据集随机 100 条，首中尾帧 + instruction + action 曲线 + filter reason。
  • pilot_export/：DROID、RoboMIND/AgiBot、EgoDex/Ego4D、LIBERO/RoboTwin 各一小份 LeRobot v3 或 WebDataset 输出。

只要这些产物站住，后面才值得谈大规模 recaption、embedding、WebDataset 打包和训练混合比例。 这也是把 PDF 中“数据统计表”变成真正 WAM 数据工程的分界线。
