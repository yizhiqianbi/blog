PhysisForcing：把物理监督塞进机器人 World Simulator

Physics Alignment · Robotic Video Generation · World Action Models

这篇的核心不是又造了一个视频大模型，而是给已有 Wan / Cosmos 这类 DiT 视频 backbone 加一套训练时物理约束：只盯住机器人、物体、接触和运动区域，同时约束点轨迹和区域关系。它证明“视频更像物理过程”不只是观感指标，也能让 WAM / action planner 的闭环成功率变高。

Robotics World Model Physics Alignment Wan / Cosmos Fast-WAM

0一句话结论

痛点。 现有视频生成模型能生成“看起来像机器人”的视频，但在接触、抓取、推动、放置时常出现轨迹断裂、物体漂移、穿模、非接触吸附等物理错误，导致它们作为 world simulator 不可靠。

核心招。 PhysisForcing 不换 backbone，而是在微调时提取物理信息区域，对 DiT 中间层同时施加像素级轨迹对齐 \(L^{phy}_{pix}\) 和语义级关系对齐 \(L^{phy}_{sem}\)。

效果。 在 R-Bench、PAI-Bench robot domain、EZS-Bench 上均提升 Wan2.2 和 Cosmos3-Nano；WorldArena action planner 闭环成功率从 16.0% 提到 24.0%；作为 Fast-WAM 视频 backbone，在 RoboTwin 2.0 平均成功率从 68.2% 到 72.8%。

代价。 训练时要跑 CoTracker3、Depth-Anything-V2、V-JEPA 2 等冻结辅助模型，数据和显存成本高；推理阶段零额外成本，但能力上限仍受底层视频 backbone 限制。

§ 1 · POSITIONING

论文定位：它不是新 world model，而是物理对齐 recipe

PhysisForcing 的任务设定是 embodied video generation / robotic world simulation：给定初始图像或视频条件和文本动作描述，预测后续机器人操作视频。论文主要把它接到 Wan2.2-I2V-A14B、Wan2.2-TI2V-5B 和 Cosmos3-Nano 上做训练时增强。

和普通视频生成相比，它不只问“画面像不像”，而是问“这个未来是否像真实物理后果”。和 Fast-WAM / WorldArena 这类 world-action 模型相比，它本身不直接输出低层 action；它提供的是更物理一致的视频 backbone，让下游 inverse dynamics 或 action planner 从更可信的 rollout 中读动作。

路线训练信号主要问题PhysisForcing 的差异
Vanilla finetuning 视频重建 / flow matching 背景像素和关键接触区域权重相近，物理信号被稀释 只在物理信息区域加强监督
几何/跟踪约束 depth、keypoint、3D structure 局部运动更稳，但不一定懂“抓住后应一起移动” 额外对齐区域间 token relation
偏好/RL 对齐 DPO、reward、judge 反馈稀疏，通常是事后压制坏样本 训练中直接在 DiT 表征层施加局部和全局物理约束

最值得记住的一点：它把“物理一致性”拆成两个层次，点轨迹负责局部连续，token relation 负责机器人和物体之间的因果耦合。
§ 2 · PIPELINE

方法总览：区域选择，然后双层对齐

input video V, text prompt c
-> CoTracker3(V): reference trajectories P_gt
-> Depth-Anything-V2(first frame): depth-aware foreground weights
-> physics-informative mask M_phy
-> video VAE + noise schedule: noisy latent z_t
-> DiT middle-layer hidden feature H_l
-> pixel alignment: track locations from feature matching, compare with P_gt
-> semantic alignment: compare DiT token relation matrix with frozen V-JEPA 2 relation matrix
-> optimize flow matching + physics losses
-> inference: discard all auxiliary models, use the finetuned video generator only

关键张量可以这样记：视频 \(V \in \mathbb{R}^{T \times C \times H \times W}\)，点轨迹 \(P=\{p_i^t\}\)，每个点位置 \(p_i^t \in \mathbb{R}^2\)。DiT 中间层特征 \(H_l\) 被 MLP 投影成帧级特征图 \(\hat{F}\in\mathbb{R}^{T\times C\times H\times W}\)。语义对齐侧把 DiT token 和 V-JEPA 2 token 对齐到同一个时空 token grid，选出 \(K\) 个 mask token 后比较 \(K\times K\) 的关系矩阵。

§ 3 · INNOVATIONS

关键创新点：旧瓶颈、改法、机制和代价

Innovation 1

Physics-informative region extraction：先找物理证据在哪里

旧方法瓶颈。 如果对整帧做均匀监督，背景、桌面、墙面这些静态区域会占掉大部分 loss；真正决定任务成败的抓手、物体、接触点反而信号弱。

它怎么改。 先用 CoTracker3 得到每个点的跨帧运动量 \(a_i\)，再用第一帧 Depth-Anything-V2 的深度估计给前景运动加权，得到 \(q_i=a_i r_i\)。分数高的轨迹被栅格化成时空 mask \(M^{phy}\)。

为什么有效。 接触丰富的操作任务里，物理错误通常集中在运动物体、机械臂末端和接触区域；把监督集中到这些地方，相当于提高关键状态变量的梯度权重。

代价/限制。 mask 质量依赖 tracker 和 depth estimator。透明物体、反光工具、遮挡、相机抖动会把错误轨迹送进 loss；论文主文用均值阈值，附录又提到 top-K 前景轨迹，具体选择策略的工程细节仍需看开源代码确认。

\[ a_i=\sum_{t=1}^{T-1}\|p_i^{t+1}-p_i^t\|_2,\qquad r_i=\frac{1}{D_0(p_i^0)+\epsilon},\qquad q_i=a_i\cdot r_i \] \[ M_i^{phy}=\mathbb{I}\left(q_i \geq \frac{1}{N}\sum_{j=1}^{N}q_j\right),\qquad M_t^{phy}(\lfloor p_i^t \rceil)=1 \]
Innovation 2

Pixel-level physics alignment：让 DiT 中间层自己能“追踪点”

旧方法瓶颈。 视频模型可能生成每帧都合理的图像，但跨帧点对应关系断掉，表现为抓手跳变、杯子瞬移、物体形变。

它怎么改。 从 DiT 中间层取特征，第一帧点特征当 query，后续帧所有空间位置当 key，用相似度 softmax 的坐标期望得到预测点位置 \(\hat{p}_i^t\)，再和 CoTracker3 提供的参考轨迹做 masked MSE。

为什么有效。 它不是在像素 RGB 上追踪，而是在 DiT 表征里要求“同一个物理点”的表征可匹配。这样约束会直接影响后续 denoising 表征，逼模型把连续运动写进内部特征。

代价/限制。 轨迹 loss 更像局部几何正则，能减少 discontinuity，但无法单独判断推动、抓取、放置这些交互结果是否语义正确。

\[ s_i^t(x)=\frac{Q(p_i^0)^\top K_t(x)}{\sqrt{C}},\qquad \hat{p}_i^t=\sum_{x\in\Omega}\mathrm{Softmax}_x(s_i^t(x))x \] \[ L_{pix}^{phy}=\frac{1}{|M^{phy}|}\left\|M^{phy}\odot(P_{pred}-P_{gt})\right\|_2^2 \]
Innovation 3

Semantic-level relational alignment：约束区域之间的相互关系

旧方法瓶颈。 点轨迹连续不代表交互正确。一个杯子可以平滑地漂走，但这仍然不符合“被夹爪抓住后随夹爪移动”的关系。

它怎么改。 用冻结 V-JEPA 2 作为 video understanding teacher，抽取同一视频的 token 表征；DiT 中间层经过 MLP 和 resize 对齐到同一 token grid。只在 \(M^{phy}\) 选中的 token 上，比较 DiT token 的 pairwise cosine relation matrix 和 V-JEPA token 的 relation matrix。

为什么有效。 绝对 feature 不同模型间很难对齐，但 token-to-token 相似度矩阵表达的是关系结构：哪些区域同动、哪些区域接触、哪些区域语义上属于同一交互。这个设计借鉴了 representation alignment 的思路，把 teacher 的关系几何迁移到生成模型内部。

代价/限制。 \(K\times K\) 关系矩阵会带来二次复杂度，论文在附录中提到 mask-selected tokens 上限可到 \(K=512\)。此外，V-JEPA 2 学到的是视觉关系，不是真正的刚体动力学或力学约束。

\[ F_u=\Phi_u(V),\qquad \hat{F}_u=\mathrm{Resize}(\psi(H_l)) \] \[ \hat{R}(i,j)=\frac{\hat{F}_i^M\cdot \hat{F}_j^M}{\|\hat{F}_i^M\|_2\|\hat{F}_j^M\|_2},\qquad R(i,j)=\frac{F_i^M\cdot F_j^M}{\|F_i^M\|_2\|F_j^M\|_2} \] \[ L_{sem}^{phy}=\frac{1}{K^2}\sum_{i=1}^{K}\sum_{j=1}^{K}|\hat{R}(i,j)-R(i,j)| \]

训练和推理：重训练时感知，轻推理时生成

Training Detail

为什么监督放在中间层

论文做了 layer ablation：Wan2.2-TI2V-5B 在 PAI-Bench robot domain 上，layer 15 得到 85.2，高于 layer 10 的 83.9、layer 20 的 84.1、layer 25 的 83.2。直觉是早层偏外观，晚层已服务于最终 noise prediction，中间层更适合承载运动和关系结构。

§ 5 · FORMULAS

公式逐行讲解：实现里对应哪些张量操作

公式符号和维度实现对应容易踩坑
\(q_i=a_i r_i\) \(a_i\) 是第 \(i\) 个点的累计 2D 运动量；\(r_i\) 是由第一帧深度得到的前景权重 CoTracker3 输出 \(625\) 个规则网格点轨迹；Depth-Anything-V2 输出归一化深度图 单目深度是相对深度；如果相机或背景运动明显，需要额外过滤
\(\hat{p}_i^t=\sum_x \mathrm{softmax}(s_i^t(x))x\) \(s_i^t\in\mathbb{R}^{H\times W}\)，输出 \(\hat{p}_i^t\in\mathbb{R}^2\) query feature 与 key feature 做点积相似度，再用 spatial soft-argmax 得到可微坐标 特征 grid 和原图坐标需要对齐；resize / patchify 后的尺度换算必须一致
\(L_{pix}^{phy}\) \(P_{pred},P_{gt}\in\mathbb{R}^{K\times T\times 2}\) 只对 mask 选中的轨迹和时间位置做 MSE CoTracker visibility 应该参与过滤；论文主文没有完整展开 visibility handling
\(\hat{R},R\in\mathbb{R}^{K\times K}\) \(K\) 是 physics mask 选出的 spatio-temporal tokens 数量，附录提到最多 \(K=512\) normalize 后做 cosine similarity matrix，比较 student/teacher relation \(K^2\) 内存成本明显；需要 token sampling 或上限裁剪
\(L=L_{FM}+\lambda_{pix}L_{pix}^{phy}+\lambda_{sem}L_{sem}^{phy}\) \(\lambda_{pix},\lambda_{sem}\) 控制两个辅助损失权重 和标准 video diffusion / rectified flow objective 同步优化 论文没有在主文给出两个 \(\lambda\) 的具体值；复现时必须等代码或自己扫参
§ 6 · TRAIN / TEST GAP

训练与推理对齐：哪里一致，哪里不一致

Aligned

一致的部分

最终推理仍然是原来的视频生成器：输入图像/文本条件和 noise schedule，输出未来视频。两个物理 loss 只改变 backbone 表征，不改变部署接口，因此可以直接替换 Fast-WAM 或 action planner 的视频 backbone。

这也是论文强调的工程价值：训练时用昂贵 teacher 和 tracker，推理时不付额外计算。

Mismatch

不一致的部分

训练时 physics target 来自真实参考视频，推理时没有参考轨迹或 V-JEPA teacher。这意味着模型学到的是分布上的物理偏置，不是在线约束。长 horizon rollout 中仍可能累计错误。

Wan2.2-I2V-A14B 的 high-noise expert 训练覆盖完整 timestep，但推理时原模型仍有高/低噪 expert 分工；这种专家路由和训练覆盖方式的细节需要代码进一步确认。

§ 7 · EXPERIMENTS

实验复盘：结果强，但要看清评测假设

实验指标和结论我怎么看
R-Bench PF-Cosmos 63.8，Cosmos3-Nano ft 61.5；PF-Wan 62.0，Wan2.2-I2V-A14B ft 57.9 提升稳定，尤其 task-oriented 维度明显；但 R-Bench 依赖 MLLM-as-judge，需要关注 judge 对物理错误的覆盖边界
PAI-Bench robot domain PF-Cosmos 85.17，Cosmos3-Nano ft 84.03；PF-Wan 81.73，Wan ft 79.90 Domain Score 提升比 Quality 更关键，说明物理语义比纯视觉质量受益更多
EZS-Bench PF-Cosmos 81.08，PF-Wan 80.54，均超过对应 vanilla ft zero-shot benchmark 证明不是简单记训练任务；但仍是生成评测，不等于真实机器人成功率
WorldArena / Fast-WAM WorldArena 16.0% 到 24.0%；Fast-WAM RoboTwin 2.0 平均 68.2% 到 72.8% 这部分最有价值：视频物理一致性转化成 action planner / policy 成功率。不过个别任务下降，例如 shake_bottle 和 stack_bowls_two，说明物理对齐不是全任务无脑增益
Ablation

消融基本支撑了主张

component ablation 显示 \(L_{pix}^{phy}\) 和 \(L_{sem}^{phy}\) 单独都提升，合用最好；region focus ablation 显示全 token 监督也有帮助，但聚焦物理区域更好；layer ablation 显示中间层最优。这三组消融分别对应“两个层次是否有用”“区域聚焦是否必要”“表征层监督是否合理”。

隐藏 confound 主要有三个：第一，R-Bench、PAI、EZS 都大量依赖视觉或 MLLM judge，可能偏向可观察的物理错误；第二，PF-Cosmos 走的是 Cosmos 官方 post-training / LoRA 设定，和 Wan 的完整微调设置不完全同构；第三，WorldArena 只评两个任务的闭环 success，能说明方向有效，但还不足以证明通用 WAM planner 已经解决。

§ 9 · IMPROVEMENTS

可能改进方向：从视觉物理走向可控物理

改动点预期收益风险验证实验
把 action tokens / proprioception 加入物理 mask 让模型知道末端执行器速度、夹爪状态、接触动作，而不只看视频 跨具身 action schema 很难统一 在 Fast-WAM 中比较 video-only PF 与 action-aware PF
引入 3D/scene flow teacher 减少 2D tracking 在遮挡和视角变化下的错误 3D 重建成本高，动态物体不稳定 对比 CoTracker-only 与 3D flow 对 contact-rich tasks 的提升
做 closed-loop rollout consistency loss 缓解推理阶段长 horizon 累积误差 训练成本大幅上升，可能牺牲单步画质 WorldArena 多步 planning success 与 video degradation 曲线
对 semantic relation 做稀疏图而非全 \(K^2\) 降低显存，聚焦接触边和同动边 图构建错误会漏掉关键关系 比较 full relation、top-k relation、contact graph relation
和真实机器人失败回放闭环 把“视频物理 plausibility”对齐到真实 policy failure mode 需要真实硬件数据和失败标注 用失败轨迹做 hard negative，评估真实/仿真成功率是否同步提升
§ 10 · MEMORY CARD

速读备忘卡

  • PhysisForcing 是训练时 recipe，不是新视频 backbone。
  • 核心问题：机器人操作视频的物理错误集中在接触和运动区域，普通重建 loss 会稀释这些区域。
  • 第一步用 CoTracker3 估计轨迹运动量，用 Depth-Anything-V2 给前景运动加权，得到 \(M^{phy}\)。
  • \(L_{pix}^{phy}\) 让 DiT 中间层通过 feature matching 预测点轨迹，并对齐 CoTracker 参考轨迹。
  • \(L_{sem}^{phy}\) 用 V-JEPA 2 的 token relation matrix 监督 DiT token relation matrix。
  • 两个 loss 分别管局部运动连续性和全局交互关系，消融显示合用最好。
  • 训练时需要 tracker、depth、video encoder；推理时全部丢掉，所以没有额外推理成本。
  • Wan2.2-I2V-A14B 只微调 high-noise expert；Cosmos3-Nano 走 LoRA post-training。
  • PF-Cosmos 在 R-Bench、PAI-Bench、EZS-Bench 都是最强结果之一。
  • WorldArena 从 16.0% 到 24.0%，说明物理更一致的视频 backbone 能改善 action planning。
  • 最大复现缺口：代码和 checkpoints 尚未开放，loss 权重、数据过滤、辅助模型缓存策略都需要等仓库更新。
