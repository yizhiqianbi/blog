Lance:
统一多模态不是把路走成一条

MaPE · Dual Experts · Flow Matching · Image/Video Generation · Understanding

这篇文章整理 Lance: Unified Multimodal Modeling by Multi-Task Synergy 和 bytedance/Lance 代码。核心判断: Lance 的统一不是 single token space,而是 shared context + decoupled pathways。语义理解和视觉生成在同一个上下文里交互,但分别用不同视觉表征、专家参数和训练目标。

Diffusion Generation Unified MM Flow Matching MaPE Qwen2.5-VL Wan2.2 VAE

0一句话结论

痛点. 统一模型要同时做图文/视频理解、图像/视频生成、编辑和 subject-driven generation,但理解需要语义特征,生成需要连续低层 latent,直接共享表征和参数会互相干扰。

核心招. Lance 把 text tokens、ViT semantic tokens、clean VAE latents、noisy VAE latents 放进同一个 interleaved context,再用 LLMUND/LLMGEN 双专家、MaPE 位置编码和 CE + flow matching 双目标分工。

效果. 3B activated parameters 在 GenEval 0.90、VBench 85.11、GEdit 7.30、MVBench 62.0,在 unified models 里非常靠前。

代价. 它不是轻量可复现 recipe:训练依赖 1.5T+300B+72B tokens 的多阶段数据、Qwen2.5-VL/Wan2.2 初始化、128 GPU 级预算和未完整释放的训练代码。

§ 1 · POSITIONING

这篇到底在解决什么:统一模型里的表征冲突

Lance 的问题设定是 native unified multimodal modeling:同一个系统支持 image/video understanding、image/video generation、editing、subject-driven generation。它不是把理解模型接一个外部生成器,也不是把所有任务都改写成离散 token next-token prediction。

主流路线有两种取舍。第一种是 Chameleon/Emu3 风格的全自回归 token 统一:接口干净,但视觉生成效率和高保真度吃亏。第二种是 BAGEL/Show-o2 风格的 AR + diffusion/flow hybrid:语言继续 next-token,视觉生成走连续 latent。Lance 属于第二类,但它更强调全 image/video 任务覆盖和多任务协同训练。

论文最重要的判断是:统一不等于完全共享。理解和生成确实需要共享上下文,这样 caption、VQA、OCR、T2I、T2V、I2V、editing 可以互相提供监督;但它们不应该强行共享同一种视觉表征和同一套 transformer 参数。

Lance 的核心不是 one model one path,而是 one context, multiple capability paths。

§ 3 · INSIGHT

关键 insight:统一上下文和解耦路径不是矛盾

旧方法瓶颈

单一路径会产生目标冲突

  • 理解想要 high-level semantic abstraction。
  • 生成想要 continuous latent 里的纹理、几何和时序细节。
  • 自回归 CE 和 flow/diffusion MSE 的优化动态不同。
  • 所有 token 共享同一套参数会让两个目标抢容量。
Lance 改法

Context 共享,representation/pathway/head 解耦

  • 共享序列让多任务上下文可以互相看见。
  • ViT 和 VAE 分别负责语义和生成 latent。
  • LLMUND 和 LLMGEN 用 token index 硬分专家路径。
  • LM head 做 next-token,latent head 做 velocity prediction。
实现洞察

代码里的 MoE 不是 router MoE

在 modeling/lance/qwen2_navit.py 里,PackedAttentionMoT 为 generation tokens 单独定义 q_proj_moe_gen/k_proj_moe_gen/v_proj_moe_gen/o_proj_moe_gen。Qwen2MoTDecoderLayer 也有独立的 mlp_moe_gen、input_layernorm_moe_gen 和 post_attention_layernorm_moe_gen。

这不是让 router 选择专家,而是由 packed_und_token_indexes 和 packed_gen_token_indexes 直接决定 token 走理解路径还是生成路径。好处是稳定、可控;代价是任务边界需要数据打包阶段清楚标出来。

§ 4 · MaPE

MaPE:给不同视觉 token 组留出位置身份

标准 Qwen2.5-VL 3D-RoPE 会给文本 token 位置 $[i,i,i]$,给视觉 token 位置 $N+[t,h,w]$。这个设计对普通图文/视频理解是够的,但 Lance 的一个样本可能同时包含 ViT semantic tokens、clean VAE condition tokens 和 noisy VAE target tokens。它们空间位置可能相近,功能角色却完全不同。

$$\hat p^{vis}_{t,h,w}=N+[t,h,w]=[N+t,N+h,N+w]$$ $$p^{(m)}_{t,h,w}=\hat p^{(m)}_{t,h,w}+[\Delta_m,0,0]$$
MaPE 只沿 temporal axis 加 modality-specific offset。这样不同 visual token groups 在全局 RoPE 空间里分开,但 spatial coordinates 不变,不会破坏图像/视频内部布局。
代码对应

repo 里没有一个叫 MaPE 的类

实现上它复用 Qwen2.5-VL 的 mrope,再在 data/common.py::shift_position_ids 里根据 sample_modality 修改 temporal coordinate。比如代码把 modality 4 移到 1000 附近,modality 3 移到 2000 附近。这个实现和论文公式一致:不是加一个新的 embedding table,而是改 RoPE position ids。

消融GenEvalGEditVBenchMVBench解读
w/ MaPE80.946.8681.8159.16编辑收益最大,说明条件图和目标 latent 的角色区分最需要位置身份。
w/o MaPE80.566.3080.9559.02不是决定性模块,但能稳定减少 token group ambiguity。
§ 5 · FORMULAS & CODE

公式和代码:从 paper loss 到 tensor 操作

Understanding loss

$$\mathcal L_{UND}=-\sum_i \log p_{\theta_{UND}}(y_i\mid y_{代码路径: lance.py 中 ce_loss_indexes 取 hidden states,过 language_model.lm_head,再对 packed_label_ids 做 cross entropy。

Generation loss

$$x_t=t x_1+(1-t)x_0,\qquad x_0\sim\mathcal N(0,I),\quad t\sim U(0,1)$$ $$\mathcal L_{GEN}=\mathbb E\left[\lVert v_{\theta_{GEN}}(x_t,S,t)-(x_1-x_0)\rVert_2^2\right]$$
论文用从 noise 到 clean 的写法。代码里采用相反时间约定: x_t=(1-t)*clean+t*noise,target 写成 noise-clean,推理从 1 到 0 做 Euler 更新。方向不同,动力学等价。

Overall objective

$$\mathcal L=\lambda_u\mathcal L_{UND}+\lambda_g\mathcal L_{GEN}$$
训练表里 CE:MSE 权重随阶段变化:PT 0.25:1,CT 0.5:1,SFT 0.25:1。这个比值决定理解任务和生成任务的梯度强度。
# Lance forward 的代码视角
packed_sequence = zeros([L, hidden])
packed_sequence[text_idx] = token_embedding(text_ids)

vit_embed = qwen25_vl_vit(pixels, grid_thw)
packed_sequence[vit_idx] = vit_embed

clean = patchify(vae_latent)                 # [num_vae_tokens, patch_latent_dim]
noise = randn_like(clean)
t = shifted_sigmoid_or_uniform_timestep(...)
x_t = (1 - t) * clean + t * noise
vae_embed = vae2llm(x_t) + time_embed(t) + latent_pos_embed(pos_ids)
packed_sequence[vae_idx] = vae_embed

h = dual_expert_llm(packed_sequence, sparse_mask, position_ids)
ce = cross_entropy(lm_head(h[ce_idx]), labels)
mse = (llm2vae(h[mse_idx]) - (noise - clean)) ** 2

批判点

“trained from scratch”需要谨慎理解

论文摘要和 README 说 Lance trained from scratch,但实验设置又说它 implemented upon Qwen2.5-VL 3B,用 Qwen2.5-VL 初始化 visual understanding encoder 和 LLMUND/LLMGEN,生成 encoder 采用 Wan2.2 3D causal VAE。

我的理解:它不是从已有 unified model 继续微调,但也不是从随机初始化训练所有组件。更准确的说法是:在 Qwen2.5-VL/Wan2.2 组件初始化之上,训练一个 native unified multimodal system。复现时不能忽略这个初始化前提。

Evidence-backed

消融确实支持 multi-task synergy

  • 加入 understanding data 后 GenEval/VBench 都涨。
  • 加入 editing/subject-driven multi-task generation 后生成和理解都受益。
  • MaPE 移除后四类 benchmark 都下降,尤其 GEdit。
Weak Spots

结论边界也要明确

  • 训练数据和 filtering recipe 不可复现。
  • VBench 使用 LLM rewriter,对比需要谨慎。
  • “from scratch”和 Qwen2.5-VL 初始化之间有表述张力。
  • repo 没有完整训练/RL 代码,只能复现实验推理链。
§ 9 · REPRODUCTION

可复现清单:真的要复现会卡在哪里

初始化. 需要 Qwen2.5-VL 3B 的 LLM/ViT 权重和 Wan2.2 3D causal VAE。随机初始化不是同一个实验。
token 打包. 必须正确维护 packed_text_indexes、packed_vit_token_indexes、packed_vae_token_indexes、split_lens、attn_modes。
attention mask. text causal,visual full/noise segment bidirectional,noise 不能错误看见其他 target noise。
MaPE. 如果启用 Qwen2.5-VL mrope,要按 modality 给 temporal coordinate shift,否则 clean/noisy/ref token 容易混。
loss 权重. CE:MSE 不是固定值,PT/CT/SFT 不同。CT 把 CE 权重提高到 0.5:1。
timestep schedule. 训练有 timestep shift,推理默认 30 steps、shift 3.5、CFG text scale 4.0。
多阶段数据. PT 只做基础 paired data 不够,CT/SFT 的 editing 和 subject-driven data 是能力来源。
代码缺口. 公开 repo 主要是 inference/benchmark/modeling,没有完整 optimizer/backward/data pipeline/RL reward 训练脚本。
不确定点合理猜测验证方式
【不确定】“trained from scratch”的精确定义可能指不是从已有 unified multimodal model 继续训练;但组件权重来自 Qwen2.5-VL/Wan2.2。看官方后续技术报告或 checkpoint 初始化说明;比较随机初始化 ablation。
【不确定】训练数据过滤和 prompt rewriting 细节内部数据质量和 prompt rewrite 对结果贡献不小。用公开数据子集复刻同架构,评估 GenEval/VBench gap。
【不确定】RL 阶段除 PaddleOCR 外是否还有其他 reward论文只明确写 text rendering/text-image alignment reward。等待训练代码或附录;检查生成文字 benchmark 的 RL 前后变化。
【不确定】image/video checkpoint 是否共享完全同一套权重README 默认区分 lance_3b 和 lance_3b_video,可能是不同 resolution/task specialization checkpoint。下载 HF 权重后比较 config/state_dict key 和 shape。
§ 10 · MEMORY CARD

速读备忘卡:下次回忆用

  • Lance 是 image/video understanding + generation + editing 的 unified multimodal model。
  • 核心不是单一路径统一,而是 shared interleaved context + decoupled capability pathways。
  • 理解用 Qwen2.5-VL ViT semantic tokens,生成用 Wan2.2 VAE continuous latent tokens。
  • LLMUND 负责 text/semantic visual tokens 和 next-token CE。
  • LLMGEN 负责 VAE latent tokens 和 flow velocity prediction。
  • MaPE 给 ViT semantic、clean VAE、noisy VAE token groups 在 temporal RoPE 维度加 offset。
  • generalized 3D causal attention:文本 causal,视觉 segment bidirectional,不同 sample 隔离。
  • 训练分 PT/CT/SFT/RL,真正的能力来自多任务数据调度。
  • 代码里的 MoE 是 token-index-based dual path,不是 router-based dynamic MoE。
  • 公开 repo 主要能看推理、benchmark、模型结构,不能完整复现训练。
  • 实验强项是 unified image/video generation 和 editing;理解能力强但仍低于专用理解模型。
  • 最大 caveat 是 “from scratch” 表述、LLM rewriter、公私数据差异和训练代码缺失。
